## 目的

定义 OpenSpec 生成的技能和命令的安装范围模型，包括范围偏好、有效范围解析以及回退/错误语义。

## 新增需求

### 需求：安装范围偏好模型
系统应支持用户级别的安装范围偏好，值为 `global` 和 `project`。

#### 场景：默认安装范围
- **当** 安装范围未显式配置时
- **那么** 系统应解析一个迁移感知的默认值：
- **并且** 对新创建的配置使用 `global`
- **并且** 对旧版本模式演进的配置使用 `project`，直到显式迁移

#### 场景：显式安装范围
- **当** 用户将安装范围配置为 `project`
- **那么** 生成和更新流程应使用 `project` 作为首选范围

### 需求：按工具面的有效范围解析
系统应根据首选范围和工具能力支持，计算每个工具面（技能、命令）的有效范围。

#### 场景：首选范围受支持
- **当** 工具面支持首选范围
- **那么** 系统应使用该范围作为有效范围

#### 场景：首选范围不受支持但备选范围受支持
- **当** 工具面不支持首选范围
- **并且** 备选范围受支持
- **那么** 系统应使用备选范围作为有效范围
- **并且** 应记录回退说明用于面向用户的输出

#### 场景：没有受支持的范围
- **当** 工具面既不支持 `global` 也不支持 `project`
- **那么** 命令应在写入文件之前失败
- **并且** 应显示可操作的修复建议

### 需求：有效范围报告
当有效范围与首选范围不同时，系统应在命令输出中报告有效范围决策。

#### 场景：回退报告
- **当** 对任何选定/配置的工具面发生回退解析
- **那么** init/update 摘要应包括每个受影响工具的有效范围说明

### 需求：跨平台路径行为
安装范围解析应生成平台正确的目标路径。

#### 场景：Windows 上的全局范围路径
- **当** 有效范围是 `global`
- **并且** 命令在 Windows 上运行
- **那么** 解析的目标路径应使用 Windows 路径约定和分隔符
- **并且** 不应直接重用 POSIX 风格的 home 相对默认值

### 需求：范围转换的清理安全性
范围转换应先更新新目标，然后安全清理旧管理目标。

#### 场景：范围变更时自动清理管理文件
- **当** update 或 init 对已配置的工具/面应用范围转换
- **那么** 系统应在清理前将新工件写入新的有效范围
- **并且** 应自动仅移除上一个有效范围中的 OpenSpec 管理文件

#### 场景：清理范围边界
- **当** 范围转换后运行清理
- **那么** 系统应保持非管理文件不变
- **并且** 应将移除范围限制在受影响的工具/工作流管理路径

#### 场景：写入成功后清理失败
- **当** 新范围中的新工件已成功写入
- **并且** 旧管理目标的清理失败
- **那么** 命令应报告失败，并附上剩余的清理路径
- **并且** 不应回滚已成功写入的新范围工件
