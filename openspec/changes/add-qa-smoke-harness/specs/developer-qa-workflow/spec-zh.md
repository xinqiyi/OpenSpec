## 新增需求

### 需求：Makefile QA 入口点

repository 应提供 Makefile 目标作为 CLI QA 流程的主要开发者入口点。

#### 场景：默认 QA 目标运行冒烟测试套件

- **WHEN** 开发者运行 `make qa`
- **THEN** 命令应执行非交互式冒烟测试套件
- **AND** 仅当所有冒烟场景通过时才以状态码 0 退出

#### 场景：冒烟测试套件目标可直接调用

- **WHEN** 开发者运行 `make qa-smoke`
- **THEN** 命令应执行与 `make qa` 相同的冒烟测试套件
- **AND** 在断言失败时返回非零退出码

#### 场景：交互式检查清单目标存在

- **WHEN** 开发者运行 `make qa-interactive`
- **THEN** 命令应提供手动交互式验证检查清单
- **AND** 默认不应运行交互式提示自动化

### 需求：沙盒化冒烟场景运行器

冒烟测试套件应在隔离的沙盒中运行 CLI 场景，使测试可重复且不依赖于机器全局状态。

#### 场景：场景执行环境隔离

- **WHEN** 冒烟场景运行时
- **THEN** 它应对 `HOME`、`XDG_CONFIG_HOME`、`XDG_DATA_HOME` 和 `CODEX_HOME` 使用临时值
- **AND** 主机机器的全局配置不应影响场景结果

#### 场景：场景制品被捕获以供审查

- **WHEN** 冒烟场景完成时
- **THEN** 运行器应捕获命令输出和退出状态
- **AND** 应捕获足够的文件系统状态以检查前后行为

#### 场景：存在高风险 workflow 覆盖

- **WHEN** 冒烟测试套件执行时
- **THEN** 它应包括涵盖配置文件/交付行为和迁移敏感流的场景
- **AND** 至少包括：
 - 非交互式工具检测
 - 配置文件未设置时的迁移
 - 交付清理（`both -> skills`、`both -> commands`）
 - 仅命令更新检测
