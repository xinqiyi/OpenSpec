## 新增需求

### 需求：按命令表面能力进行交付同步
update 命令应使用每个已配置工具的命令表面能力来同步制品。

#### 场景：为适配器支持的已配置工具进行命令交付
- **WHEN** 用户运行 `openspec update`
- **AND** 交付设置为 `commands`
- **AND** 已配置工具具有适配器支持的命令表面
- **THEN** 系统应为活跃 workflow 生成或刷新命令文件
- **AND** 系统应移除该工具的受管 skill 目录

#### 场景：为可调用 skill 类型的已配置工具进行命令交付
- **WHEN** 用户运行 `openspec update`
- **AND** 交付设置为 `commands`
- **AND** 已配置工具具有 `skills-invocable` 命令表面能力
- **THEN** 系统应为活跃 workflow 生成或刷新受管 skill 目录
- **AND** 系统不应将那些受管 skill 目录作为仅命令清理的一部分移除
- **AND** 系统不应要求为该工具生成适配器命令文件

#### 场景：命令交付但命令表面不受支持
- **WHEN** 用户运行 `openspec update`
- **AND** 交付设置为 `commands`
- **AND** 已配置工具没有命令表面能力
- **THEN** 系统应在应用部分更新前以退出码 1 失败
- **AND** 输出应标识不兼容的工具和推荐的补救措施

### 需求：可调用 skill 类型命令表面的已配置工具检测
update 命令应将具有可调用 skill 类型命令表面的工具视为已配置工具（当受管 skill 制品存在时），包括在命令交付 schema 下。

#### 场景：命令交付下的可调用 skill 类型工具
- **WHEN** 用户运行 `openspec update`
- **AND** 交付设置为 `commands`
- **AND** 工具没有适配器生成的命令文件
- **AND** 该工具标记为 `skills-invocable` 且已安装受管 skill
- **THEN** 系统应将该工具包含在已配置工具检测中
- **AND** 系统应对该工具应用正常的版本/配置文件/交付同步

### 需求：更新总结反映每个工具的有效交付
update 命令应在交付意图和制品类型因工具能力不同时报告有效的制品行为。

#### 场景：命令交付中的可调用 skill 类型工具总结
- **WHEN** 更新成功完成
- **AND** 交付为 `commands`
- **AND** 至少有一个更新的工具是 `skills-invocable`
- **THEN** 输出应包含一条清晰的说明，指出这些工具使用 skill 作为其命令表面
- **AND** 输出应避免暗示命令生成因错误而被跳过
