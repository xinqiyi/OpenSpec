# List 命令 spec

## 目的

`openspec list` 命令应为开发者提供项目中所有活跃变更的快速概览，显示其名称和任务完成状态。

## 行为

### 命令执行

当 `openspec list` 被执行时
那么扫描 `openspec/changes/` 目录中的变更目录
并且从结果中排除 `archive/` 子目录
并且解析每个变更的 `tasks.md` 文件以统计任务完成情况

### 任务统计

当解析 `tasks.md` 文件时
那么统计符合以下 schema 的任务：
- 已完成：包含 `- [x]` 的行
- 未完成：包含 `- [ ]` 的行
并且将总任务数计算为已完成和未完成之和

### 输出格式

当显示列表时
那么显示包含以下列的表格：
- 变更名称（目录名）
- 任务进度（例如"3/5 任务"或"✓ 已完成"）
- 状态指示器：
 - `✓` 表示完全完成的变更（所有任务完成）
 - 进度分数表示部分完成

输出示例：
```
变更：
 add-auth-feature 3/5 任务
 update-api-docs ✓ 已完成
 fix-validation 0/2 任务
 add-list-command 1/4 任务
```

### 空状态

当没有活跃变更时（仅有 archive/ 或空的 changes/）
那么显示："未找到活跃变更。"

### 错误处理

如果变更目录没有 `tasks.md` 文件
那么以"无任务"状态显示该变更

如果 `openspec/changes/` 目录不存在
那么显示错误："未找到 OpenSpec 变更目录。请先运行 'openspec init'。"
并以退出码 1 退出

### 排序

变更应按变更名称字母顺序显示，以保持一致性。

## 为什么

开发者需要一种快速方式：
- 查看哪些变更正在进行中
- 识别哪些变更已准备好 archive
- 了解整体项目的演进状态
- 无需打开多个文件即可获得概览

该命令以最小的代价提供这种可见性，遵循 OpenSpec 简洁和清晰的理念。
