# CLI Init 规范

## 目的

`openspec init` 命令应在任何项目中创建完整的 OpenSpec 目录结构，支持立即采用 OpenSpec 约定，并兼容多个 AI 编码助手。

## 行为

### 进度指示器

当执行初始化步骤时
那么在后台静默验证环境（无输出，除非出错）
并且使用 ora 旋转指示器显示进度：
- 显示旋转指示器："⠋ 正在创建 OpenSpec 结构..."
- 然后成功："✔ OpenSpec 结构已创建"
- 显示旋转指示器："⠋ 正在配置 AI 工具..."
- 然后成功："✔ AI 工具已配置"

### 目录创建

当执行 `openspec init` 时
那么创建以下目录结构：
```
openspec/
├── project.md
├── README.md
├── specs/
└── changes/
    └── archive/
```

### 文件生成

该命令应生成：
- `README.md`，包含给 AI 助手的完整 OpenSpec 说明
- `project.md`，包含项目上下文模板

### AI 工具配置

当以交互方式运行时
那么提示用户选择要配置的 AI 工具：
- Claude Code（更新/创建带有 OpenSpec 标记的 CLAUDE.md）
- Cursor（未来）
- Aider（未来）

### AI 工具配置详情

当选择了 Claude Code 时
那么在项目根目录（不在 openspec/ 内部）创建或更新 `CLAUDE.md`

当 CLAUDE.md 不存在时
那么创建新文件，内容包含在标记中的 OpenSpec 内容：
```markdown
<!-- OPENSPEC:START -->
# OpenSpec 项目

本文档为 AI 编码助手提供如何使用 OpenSpec 约定进行规范驱动开发的说明。在使用 OpenSpec 启用的项目时，请精确遵循这些规则。

本项目使用 OpenSpec 进行规范驱动开发。规范是事实来源。

参见 @openspec/README.md 了解详细的约定和指南。
<!-- OPENSPEC:END -->
```

当 CLAUDE.md 已存在时
那么保留所有现有内容
并且使用标记在文件开头插入 OpenSpec 内容
并且确保标记不会重复（如果它们已经存在）

标记系统应：
- 使用 `<!-- OPENSPEC:START -->` 标记托管内容的开始
- 使用 `<!-- OPENSPEC:END -->` 标记托管内容的结束
- 允许 OpenSpec 更新其内容而不影响用户自定义
- 完整保留标记之外的所有内容

为什么使用标记：
- 用户可能已有想要保留的现有 CLAUDE.md 指令
- OpenSpec 可以在未来版本中更新其指令
- OpenSpec 管理和用户管理内容之间有清晰的边界

### 交互模式

当运行时
那么提示用户："您使用哪个 AI 工具？"
并且显示可用工具的单项选择菜单：
- Claude Code
并且显示"即将推出"的禁用选项（不可选择）：
- Cursor（即将推出）
- Aider（即将推出）
- Continue（即将推出）

用户导航：
- 使用箭头键在选项之间移动
- 按 Enter 选择高亮选项

### 安全检查

当 `openspec/` 目录已存在时
那么显示错误，带 ora 失败指示器：
"✖ 错误：OpenSpec 似乎已经初始化。使用 'openspec update' 更新结构。"

当检查初始化可行性时
那么在目标目录中静默验证写权限
并且仅在权限不足时显示错误

### 成功输出

当初始化成功完成时
那么显示面向 AI 驱动工作流的可操作提示：
```
✔ OpenSpec 初始化成功！

下一步 - 将这些提示复制到 Claude：

────────────────────────────────────────────────────────────
1. 填写您的项目上下文：
   "请阅读 openspec/project.md 并帮助我填写
    我的项目、技术栈和约定的详细信息"

2. 创建您的第一个变更提案：
   "我想添加 [您的功能名称]。请为此功能创建一个
    OpenSpec 变更提案"

3. 学习 OpenSpec 工作流：
   "请解释 openspec/README.md 中的 OpenSpec 工作流，
    以及我应如何在 这个项目中与您协作"
────────────────────────────────────────────────────────────
```

这些提示应：
- 可复制粘贴以便立即与 AI 工具使用
- 引导用户完成 AI 驱动的工作流
- 替换占位文本（[您的功能名称]）为实际功能

### 退出码

- 0：成功
- 1：一般错误（包括 OpenSpec 目录已存在时）
- 2：权限不足（保留供将来使用）
- 3：用户取消操作（保留供将来使用）

## 原因

手动创建 OpenSpec 结构容易出错，并造成采用摩擦。标准化的 init 命令确保：
- 所有项目中的结构一致
- 始终包含正确的 AI 指令文件
- 新项目快速上手
- 从一开始就有清晰的约定
