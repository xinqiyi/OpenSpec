## 实现说明

### 关键设计决策

1. **非阻塞确认行为**：当用户交互式拒绝 spec 更新时，archive 操作继续而非完全取消。这是一个关键的 UX 改进，因为：
 - 用户可能希望在更新之前单独审查 spec
 - archive 工作不应被 spec 审查决策阻塞
 - 在部署 workflow 中保持灵活性

2. **标志命名约定**：选择 `--skip-specs` 以保持清晰和一致性：
 - 清晰指示操作（跳过）和目标（spec）
 - 遵循 CLI 标志的 kebab-case 约定
 - 自然地转换为代码中的 `skipSpecs` camelCase

3. **控制台消息策略**：为所有跳过 spec 场景添加了显式消息：
 - 使用标志时："正在跳过 spec 更新（已提供 --skip-specs 标志）。"
 - 用户拒绝时："正在跳过 spec 更新。继续 archive。"
 - 确保用户始终了解 spec 的处理情况

4. **测试覆盖方法**：为以下情况创建了单独的测试用例：
 - 基于标志的跳过（通过 CLI 的显式用户选择）
 - 交互式拒绝（运行时的用户决策）
 - 两者验证相同的结果但测试不同的代码路径

### 解决的用例

- **基础设施变更**：构建工具、CI/CD、依赖项的变更
- **文档更新**：README 更新、注释改进
- **工具修改**：开发者工具、脚本、配置文件
- **重构**：不改变功能/spec 的代码改进

### 未来考虑

- 可能自动检测变更何时不包含 spec 并建议使用该标志
- 可能需要跟踪哪些 archive 跳过了 spec 更新以用于审计目的
