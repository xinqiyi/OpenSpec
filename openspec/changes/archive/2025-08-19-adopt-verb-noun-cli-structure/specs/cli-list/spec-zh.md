# delta：CLI List 命令

## 修改后的需求

### 需求：命令执行
命令应根据选定的 schema 扫描并分析活跃变更或 spec。

#### 场景：扫描变更（默认）
- **WHEN** `openspec list` 在没有标志的情况下执行
- **THEN** 扫描 `openspec/changes/` 目录中的变更目录
- **AND** 从结果中排除 `archive/` 子目录
- **AND** 解析每个变更的 `tasks.md` 文件以统计任务完成情况

#### 场景：扫描 spec
- **WHEN** `openspec list --specs` 被执行
- **THEN** 扫描 `openspec/specs/` 目录中的能力
- **AND** 读取每个能力的 `spec.md`
- **AND** 解析需求以计算需求数量

### 需求：输出格式
命令应以清晰可读的表格格式显示项目，并带有 schema 适当的进度或计数。

#### 场景：显示变更列表（默认）
- **WHEN** 显示变更列表时
- **THEN** 显示包含以下列的表格：
 - 变更名称（目录名）
 - 任务进度（例如"3/5 任务"或"✓ 已完成"）

#### 场景：显示 spec 列表
- **WHEN** 显示 spec 列表时
- **THEN** 显示包含以下列的表格：
 - spec ID（目录名）
 - 需求数量（例如"需求 12"）

### 需求：空状态
命令应在选定 schema 下没有项目时提供清晰的反馈。

#### 场景：处理空状态（变更）
- **WHEN** 没有活跃变更时（仅有 archive/ 或空的 changes/）
- **THEN** 显示："未找到活跃变更。"

#### 场景：处理空状态（spec）
- **WHEN** 没有 spec 目录或目录中没有能力时
- **THEN** 显示："未找到 spec。"

### 需求：标志
命令应接受标志以选择被列出的名词。

#### 场景：选择 spec
- **WHEN** 提供了 `--specs`
- **THEN** 列出 spec 而非变更

#### 场景：选择变更
- **WHEN** 提供了 `--changes`
- **THEN** 显式列出变更（与默认行为相同）
