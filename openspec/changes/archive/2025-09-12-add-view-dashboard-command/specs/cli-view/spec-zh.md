# CLI View 命令 - 变更

## 新增需求

### 需求：仪表盘显示

系统应提供一个 `view` 命令，显示 spec 和变更的仪表盘概览。

#### 场景：基本仪表盘显示

- **WHEN** 用户运行 `openspec view`
- **THEN** 系统显示格式化的仪表盘，包含摘要、活跃变更、已完成变更和 spec 等部分

#### 场景：无 OpenSpec 目录

- **WHEN** 用户在无 OpenSpec 的目录中运行 `openspec view`
- **THEN** 系统显示错误消息"未找到 openspec 目录"

### 需求：摘要部分

仪表盘应显示包含关键项目指标的摘要部分。

#### 场景：完整摘要显示

- **WHEN** 仪表盘渲染了 spec 和变更
- **THEN** 系统显示 spec 总数和需求总数
- **AND** 显示进行中的活跃变更数量
- **AND** 显示已完成的变更数量
- **AND** 显示总体任务进度百分比

#### 场景：空项目摘要

- **WHEN** 没有 spec 或变更存在
- **THEN** 摘要显示所有指标为零

### 需求：活跃变更显示

仪表盘应显示活跃变更并附带视觉进度指示器。

#### 场景：带进度条的活跃变更

- **WHEN** 存在进行中的带任务变更
- **THEN** 系统显示每个变更，变更名称左对齐
- **AND** 使用 Unicode 字符显示视觉进度条
- **AND** 右侧显示完成百分比

#### 场景：无活跃变更

- **WHEN** 所有变更已完成或没有变更存在
- **THEN** 活跃变更部分从显示中省略

### 需求：已完成变更显示

仪表盘应在单独的部分中列出已完成的变更。

#### 场景：已完成变更列表

- **WHEN** 存在已完成的变更（所有任务完成）
- **THEN** 系统在专用部分中显示它们，并带有勾选标记指示符

#### 场景：混合完成状态

- **WHEN** 部分变更已完成，其他变更活跃
- **THEN** 系统将它们分到相应的部分

### 需求：spec 显示

仪表盘应按需求数量排序显示 spec。

#### 场景：带计数的 spec 列表

- **WHEN** 项目中存在 spec
- **THEN** 系统按需求数量降序显示 spec，并带有计数标签

#### 场景：解析错误的 spec

- **WHEN** spec 文件无法解析
- **THEN** 系统将其包含在内，需求数量计为 0

### 需求：视觉格式化

仪表盘应使用一致的视觉格式，包含颜色和符号。

#### 场景：颜色编码

- **WHEN** 仪表盘元素被显示
- **THEN** 系统使用青色表示 spec 项目
- **AND** 使用黄色表示活跃变更
- **AND** 使用绿色表示已完成项目
- **AND** 使用暗灰色表示辅助文本

#### 场景：进度条渲染

- **WHEN** 显示进度条时
- **THEN** 系统使用实心块（█）表示已完成部分，使用浅色块（░）表示剩余部分

### 需求：错误处理

view 命令应优雅地处理错误。

#### 场景：文件系统错误

- **WHEN** 文件系统操作失败
- **THEN** 系统使用可用数据继续，并跳过无法访问的项目

#### 场景：无效的数据结构

- **WHEN** spec 或变更具有无效格式
- **THEN** 系统跳过无效项目并继续渲染
