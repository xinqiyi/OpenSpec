# 变更：按进度对活跃变更排序

## 问题
- 仪表盘目前按文件系统发现顺序列出活跃变更。
- 用户无法快速发现尚未开始或接近完成的提案。
- 不同运行之间排序不一致，使得在存在多个变更时更难跟踪进度。

## 提议
1. 更新仪表盘中的活跃变更列表，按完成百分比升序排序，使 0% 的项目排在前面。
2. 当两个变更具有相同的完成百分比时，按变更标识符（字母顺序）确定性地打破平局。

## 优势
- 突出尚未开始的工作，便于更快确定优先级。
- 在不同机器和重复运行之间提供一致的排序。
- 保持仪表盘简洁，同时传达最重要的状态信号。

## 风险与应对措施
- **风险：** 当进度数据缺失时，排序逻辑可能导致渲染异常。
  - **应对措施：** 将缺失的进度视为 0%，确保项目仍然显示，并在测试中记录此行为。
- **风险：** 额外的排序可能影响大型变更集的性能。
  - **应对措施：** 活跃变更的数量通常很少；对少量条目进行排序的开销可忽略不计。

## 成功标准
- 仪表盘输出的活跃变更按完成百分比升序排列，并具有确定性的平局处理。
- 单元测试覆盖百分比不同以及出现平局时的排序验证。
