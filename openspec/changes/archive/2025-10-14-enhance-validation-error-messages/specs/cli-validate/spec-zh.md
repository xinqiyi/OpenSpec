## 修改后的需求
### 需求：验证应提供可操作的修复步骤
验证输出应包含针对每个错误的特定指导，包括预期结构、示例标题和建议用于验证修复的命令。

#### 场景：变更中未找到增量
- **当** 验证具有零解析增量的变更时
- **则** 显示错误"未找到增量"，并提供指导：
  - 解释变更规范必须包含 `## 新增需求`、`## 修改后的需求`、`## 移除的需求` 或 `## 重命名的需求`
  - 提醒作者文件必须位于 `openspec/changes/{id}/specs/<capability>/spec.md` 下
  - 包含明确提示："规范增量文件在操作标题前不能以标题开头"
  - 建议运行 `openspec change show {id} --json --deltas-only` 进行调试

#### 场景：缺少必需部分
- **当** 缺少必需部分时
- **则** 包含预期的标题名称和最小骨架：
  - 对于规范：`## 目的`、`## 需求`
  - 对于变更：`## 为什么`、`## 变更内容`
  - 提供缺失部分的示例片段，带有可复制的占位符文案
  - 提及 `openspec/AGENTS.md` 中的快速参考部分是权威模板

#### 场景：缺少需求描述文本
- **当** 需求标题在场景之前缺少描述文本时
- **则** 发出错误，解释 `### Requirement:` 行后必须跟叙述性文本，然后才能出现 `#### Scenario:` 标题
  - 显示合规示例："### Requirement: Foo" 后跟 "系统应……"
  - 建议在列出场景之前添加 1-2 句描述规范行为的句子
  - 引用 `openspec/AGENTS.md` 中的预验证检查清单

### 需求：验证器应检测可能的格式错误场景并发出修复警告
验证器应识别看起来像场景的带项目符号的行（例如，以 WHEN/THEN/AND 开头的行），并发出有针对性的警告，附带转换为 `#### Scenario:` 的示例。

#### 场景：需求下的带项目符号的 WHEN/THEN
- **当** 在需求下发现以 WHEN/THEN/AND 开头的项目符号，但没有任何 `#### Scenario:` 标题时
- **则** 发出警告："场景必须使用 '#### Scenario:' 标题"，并显示转换模板：
```
#### 场景：简短名称
- **当** ...
- **则** ...
- **并且** ...
```
