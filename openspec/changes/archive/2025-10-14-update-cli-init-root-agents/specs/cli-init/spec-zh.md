## 修改后的需求
### 需求：AI 工具配置
该命令应使用分组选择体验来配置带有 OpenSpec 指令的 AI 编码助手，使团队能够启用原生集成，同时始终为其他助手提供指南。

#### 场景：提示 AI 工具选择
- **WHEN** 以交互方式运行时
- **THEN** 呈现一个多选向导，将选项分为两个标题：
 - **原生支持的提供商**显示每个可用的第一方集成（Claude Code、Cursor、OpenCode 等）并带有复选框
 - **其他工具**说明根级 `AGENTS.md` 存根始终为兼容 AGENTS 的助手生成，且不可取消选择
- **AND** 将已配置的原生工具标记为"（已配置）"，以表明选择它们将刷新托管内容
- **AND** 将禁用或不可用的提供商标记为"即将推出"，以便用户知道他们尚无法选择
- **AND** 允许在未选择任何原生提供商时确认选择，因为根级存根默认保持启用
- **AND** 在扩展 schema 下将基本提示文案改为"您想添加或刷新哪些原生支持的 AI 工具？"

### 需求：退出码调整
`openspec init` 应将未选择新原生工具的扩展 schema 视为成功的刷新。

#### 场景：允许空的扩展运行
- **WHEN**OpenSpec 已初始化且用户未选择额外的原生支持工具时
- **THEN** 成功完成，同时刷新根级 `AGENTS.md` 存根
- **AND** 以退出码 0 退出

## 新增需求
### 需求：根级指令存根
`openspec init` 应始终搭建根级 `AGENTS.md` 交办说明，以便每个团队成员都能找到主要的 OpenSpec 指令。

#### 场景：创建根级 `AGENTS.md`
- **GIVEN** 项目可能已包含或未包含 `AGENTS.md` 文件
- **WHEN** 在全新或扩展 schema 下初始化完成时
- **THEN** 使用 `TemplateManager.getAgentsStandardTemplate()` 的托管标记块在 repository 根目录创建或刷新 `AGENTS.md`
- **AND** 保留托管标记外的任何现有内容，同时替换标记内的存根文本
- **AND** 无论选择了哪些原生 AI 工具，都创建存根
