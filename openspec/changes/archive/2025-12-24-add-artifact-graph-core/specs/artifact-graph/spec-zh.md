## 新增需求

### 需求：模式加载
系统应从 YAML 模式文件加载工件图定义。

#### 场景：加载有效模式
- **当** 提供了有效的模式 YAML 文件
- **则** 系统返回包含所有工件和依赖的 ArtifactGraph

#### 场景：拒绝无效模式
- **当** 模式 YAML 文件缺少必填字段
- **则** 系统抛出带有描述性消息的错误

#### 场景：检测到循环依赖
- **当** 模式包含循环的工件依赖
- **则** 系统抛出错误，列出循环中的工件 ID

#### 场景：无效的依赖引用
- **当** 工件的 `requires` 数组引用了不存在的工件 ID
- **则** 系统抛出错误，标识无效引用

#### 场景：拒绝重复工件 ID
- **当** 模式包含多个具有相同 ID 的工件
- **则** 系统抛出错误，标识重复项

### 需求：构建顺序计算
系统应计算工件的有效拓扑构建顺序。

#### 场景：线性依赖链
- **当** 工件形成线性链（A → B → C）
- **则** getBuildOrder() 返回 [A, B, C]

#### 场景：菱形依赖
- **当** 工件形成菱形（A → B, A → C, B → D, C → D）
- **则** getBuildOrder() 返回 A 在 B 和 C 之前，D 在最后

#### 场景：独立工件
- **当** 工件没有依赖
- **则** getBuildOrder() 以稳定的顺序返回它们

### 需求：状态检测
系统应通过扫描文件系统检测工件完成状态。

#### 场景：简单文件存在
- **当** 工件生成 "proposal.md" 且该文件存在
- **则** 工件标记为已完成

#### 场景：简单文件缺失
- **当** 工件生成 "proposal.md" 但该文件不存在
- **则** 工件未标记为已完成

#### 场景：包含文件的 Glob 模式
- **当** 工件生成 "specs/*.md" 且 specs/ 目录包含 .md 文件
- **则** 工件标记为已完成

#### 场景：空的 Glob 模式
- **当** 工件生成 "specs/*.md" 但 specs/ 目录为空或不存在
- **则** 工件未标记为已完成

#### 场景：缺少变更目录
- **当** 变更目录不存在
- **则** 所有工件标记为未完成（空状态）

### 需求：就绪工件查询
系统应基于依赖完成情况识别哪些工件可以创建。

#### 场景：根工件初始就绪
- **当** 没有工件已完成
- **则** getNextArtifacts() 返回没有依赖的工件

#### 场景：依赖工件变为就绪
- **当** 工件的所有依赖都已完成
- **则** getNextArtifacts() 包含该工件

#### 场景：排除被阻塞的工件
- **当** 工件有未完成的依赖
- **则** getNextArtifacts() 不包含该工件

### 需求：完成检查
系统应确定图中的所有工件何时完成。

#### 场景：全部完成
- **当** 图中的所有工件都在完成集合中
- **则** isComplete() 返回 true

#### 场景：部分完成
- **当** 图中的部分工件未完成
- **则** isComplete() 返回 false

### 需求：阻塞查询
系统应识别哪些工件被阻塞，并返回其所有未满足的依赖。

#### 场景：工件被单依赖阻塞
- **当** 工件 B 需要工件 A 且 A 未完成
- **则** getBlocked() 返回 `{ B: ['A'] }`

#### 场景：工件被多依赖阻塞
- **当** 工件 C 需要 A 和 B，且只有 A 已完成
- **则** getBlocked() 返回 `{ C: ['B'] }`

#### 场景：工件被所有依赖阻塞
- **当** 工件 C 需要 A 和 B，且两者都未完成
- **则** getBlocked() 返回 `{ C: ['A', 'B'] }`
