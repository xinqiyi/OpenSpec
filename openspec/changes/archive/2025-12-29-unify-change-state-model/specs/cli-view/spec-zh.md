# cli-view 规范增量

## 新增需求

### 需求：草稿变更显示

仪表板应在单独的"草稿"部分显示没有任务的变更。

#### 场景：草稿变更列表

- **当** 存在没有 tasks.md 或定义了零个任务的变更
- **那么** 系统在"草稿变更"部分显示它们
- **并且** 使用不同的指示器（例如 `○`）显示草稿状态

#### 场景：草稿部分排序

- **当** 存在多个草稿变更
- **那么** 系统按名称字母顺序排序

## 修改后的需求

### 需求：已完成变更显示

仪表板应在单独的部分列出已完成的变更，仅显示所有任务都完成的变更。

> **修复了错误**：之前，`total === 0` 的变更被错误地显示为已完成。

#### 场景：已完成变更列表

- **当** 存在 `tasks.total > 0` 且 `tasks.completed === tasks.total` 的变更
- **那么** 系统在专用部分用勾选标记指示器显示它们

#### 场景：混合完成状态

- **当** 部分变更已完成而其他变更处于活跃状态
- **那么** 系统将它们分离到适当的章节

#### 场景：空变更未完成

- **当** 变更没有 tasks.md 或定义了零个任务
- **那么** 系统不会将其显示在"已完成变更"部分
- **并且** 而是显示在"草稿变更"部分

### 需求：摘要部分

仪表板应显示包含关键项目指标的摘要部分，包括草稿变更计数。

#### 场景：完整摘要显示

- **当** 仪表板渲染了规范和变更
- **那么** 系统显示规范和需求的总数
- **并且** 显示草稿变更的数量
- **并且** 显示进行中的活跃变更数量
- **并且** 显示已完成的变更数量
- **并且** 显示总体任务进度百分比

#### 场景：空项目摘要

- **当** 不存在规范或变更
- **那么** 摘要显示所有指标的零计数
