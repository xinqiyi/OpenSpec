## 原因

规范应用目前与归档捆绑在一起 - 用户必须运行 `openspec archive` 才能将 delta 规范应用到主规范。这耦合了两个不同的关注点（应用规范 vs 归档变更），并迫使用户等到"完成"后才能看到主规范更新。用户希望在工作流中更灵活地提前同步规范，特别是在迭代期间。

## 变更内容

- 添加 `/opsx:sync` 技能，将 delta 规范同步到主规范作为独立操作
- 该操作是幂等的 - 多次运行安全，Agent 合并主规范以匹配 delta
- 归档继续像今天一样工作（如果尚未合并则应用规范，然后移动到归档）
- 无新的状态跟踪 - Agent 读取 delta 和主规范，每次运行时合并
- Agent 驱动的方法允许智能合并（部分更新、添加场景）

**工作流变为：**
```
/opsx:new → /opsx:continue → /opsx:apply → archive
                                  │
                                  └── /opsx:sync（可选，随时）
```

## 能力

### 新增能力
- `specs-sync-skill`：`/opsx:sync` 命令的技能模板，将主规范与 delta 规范合并

### 修改的能力
- 无（Agent 驱动，无需 CLI 命令）

## 影响范围

- **技能**：`skill-templates.ts` 中的新 `openspec-sync-specs` 技能
- **归档**：无需更改 - 已进行合并，将继续工作
- **Agent 工作流**：用户获得在归档前同步规范的灵活性
