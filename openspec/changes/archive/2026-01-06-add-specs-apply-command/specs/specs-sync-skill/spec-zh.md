## 新增需求

### 需求：Specs Sync 技能
系统应提供 `/opsx:sync` 技能，用于将变更的增量规范同步到主规范。

#### 场景：将增量规范同步到主规范
- **当** agent 使用变更名称执行 `/opsx:sync`
- **那么** agent 从 `openspec/changes/<name>/specs/` 读取增量规范
- **并且** 从 `openspec/specs/` 读取对应的主规范
- **并且** 协调主规范以匹配增量所描述的内容

#### 场景：幂等操作
- **当** agent 对同一变更多次执行 `/opsx:sync`
- **那么** 结果与运行一次相同
- **并且** 不会创建重复的需求

#### 场景：变更选择提示
- **当** agent 执行 `/opsx:sync` 时未指定变更
- **那么** agent 提示用户从可用变更中选择
- **并且** 显示具有增量规范的变更

### 需求：增量协调逻辑
agent 应使用增量操作标题协调主规范与增量规范。

#### 场景：新增需求
- **当** 增量包含 `## 新增需求` 及一个需求
- **并且** 该需求在主规范中不存在
- **那么** 将该需求添加到主规范

#### 场景：新增需求已存在
- **当** 增量包含 `## 新增需求` 及一个需求
- **并且** 主规范中已存在同名需求
- **那么** 更新现有需求以匹配增量版本

#### 场景：修改后的需求
- **当** 增量包含 `## 修改后的需求` 及一个需求
- **并且** 该需求在主规范中存在
- **那么** 用增量版本替换主规范中的需求

#### 场景：移除的需求
- **当** 增量包含 `## 移除的需求` 及一个需求名称
- **并且** 该需求在主规范中存在
- **那么** 从主规范中移除该需求

#### 场景：重命名的需求
- **当** 增量包含 `## 重命名的需求` 且格式为 FROM:/TO:
- **并且** FROM 中的需求在主规范中存在
- **那么** 将需求重命名为 TO 中的名称

#### 场景：新的能力规范
- **当** 增量规范中存在主规范中没有的能力
- **那么** 在 `openspec/specs/<能力>/spec.md` 创建新的主规范文件

### 需求：技能输出
技能应提供关于已同步内容的清晰反馈。

#### 场景：显示已同步的更改
- **当** 协调成功完成
- **那么** 显示按能力分类的更改摘要：
  - 新增需求数量
  - 修改需求数量
  - 移除需求数量
  - 重命名需求数量

#### 场景：无需更改
- **当** 主规范已与增量规范匹配
- **那么** 显示"规范已同步 - 无需更改"
