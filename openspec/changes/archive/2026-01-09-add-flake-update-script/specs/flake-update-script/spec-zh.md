## 新增的需求

### 需求：动态版本支持

脚本应支持从 package.json 动态读取版本的 flake.nix 配置。

#### 场景：版本验证
- **WHEN** 脚本运行时
- **THEN** 使用 Node.js 从 package.json 读取版本
- **AND** 脚本验证 flake.nix 使用动态版本 schema
- **AND** 如果检测到硬编码版本则发出警告

#### 场景：版本显示
- **WHEN** 脚本运行时
- **THEN** 脚本显示当前包版本
- **AND** 指示版本由 flake.nix 动态读取

### 需求：自动哈希确定

脚本应自动确定并更新正确的 pnpm 依赖哈希。

#### 场景：触发构建以获取哈希
- **WHEN** 脚本需要确定正确的哈希
- **THEN** 脚本在 flake.nix 中设置占位哈希
- **AND** 运行 nix build，该命令会因哈希错误而失败
- **AND** 从构建错误输出中提取正确的哈希

#### 场景：从构建输出提取哈希
- **WHEN** nix build 因哈希不匹配而失败
- **THEN** 脚本从错误输出中解析 "got: sha256-..."
- **AND** 使用正确的哈希更新 flake.nix

#### 场景：哈希更新失败
- **WHEN** 脚本无法从构建输出中提取哈希
- **THEN** 脚本将 flake.nix 恢复为原始哈希
- **AND** 以错误码 1 退出
- **AND** 显示构建输出以供调试

### 需求：构建验证

脚本应在更新后验证 flake.nix 能否成功构建。

#### 场景：验证成功
- **WHEN** 哈希已更新
- **THEN** 脚本运行 nix build 进行验证
- **AND** 如果构建完成则报告成功

#### 场景：Git 树脏警告
- **WHEN** 构建成功但 git 树是脏的
- **THEN** 脚本报告脏树警告
- **AND** 仍然指示构建成功

### 需求：用户反馈

脚本应提供清晰的进度信息和后续步骤。

#### 场景：进度报告
- **WHEN** 脚本运行时
- **THEN** 每一步都附带描述性消息进行报告
- **AND** 显示检测到的版本和哈希

#### 场景：成功摘要
- **WHEN** 脚本成功完成
- **THEN** 摘要显示版本和哈希变更
- **AND** 显示后续步骤（测试、验证、提交）

#### 场景：无需更改
- **WHEN** 哈希已经是最新
- **THEN** 脚本报告无需更改
- **AND** 以成功码 0 退出

### 需求：脚本安全性

脚本应在出错时快速失败并使用安全默认值。

#### 场景：Bash 错误处理
- **WHEN** 脚本遇到错误
- **THEN** 脚本立即退出（set -e）
- **AND** 未定义变量导致退出（set -u）
- **AND** 管道失败被捕获（set -o pipefail）

#### 场景：文件路径解析
- **WHEN** 脚本确定文件位置时
- **THEN** 路径相对于脚本位置计算
- **AND** 脚本无论工作目录如何都能正常工作

### 需求：文档

系统应为更新脚本提供文档。

#### 场景：脚本使用文档
- **WHEN** 维护者需要使用更新脚本
- **THEN** scripts/README.md 解释何时以及如何使用它
- **AND** 提供示例 workflow

#### 场景：脚本列表
- **WHEN** 维护者查看 scripts/README.md
- **THEN** 所有维护脚本都有文档记录
- **AND** 每个脚本的用途清晰明了
