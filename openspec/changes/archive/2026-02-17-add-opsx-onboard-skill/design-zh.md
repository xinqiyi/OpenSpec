## 上下文

OpenSpec 拥有完整的 skill 和斜杠命令生成系统。skill 在 `src/core/templates/skill-templates.ts` 中定义为返回 `SkillTemplate` 对象（用于 agent skill）和 `CommandTemplate` 对象（用于斜杠命令）的函数。这些在 `src/core/shared/skill-generation.ts` 中注册，并在 `openspec init` 和 `openspec update` 期间生成。

现有 skill 遵循一致的 schema：
- `getXxxSkillTemplate()` 返回具有名称、描述、指令的 skill
- `getOpsxXxxCommandTemplate()` 返回具有名称、描述、类别、标签、内容的斜杠命令
- 两者都在 `skill-generation.ts` 的各自数组中进行注册

## 目标 / 非目标

**目标：**
- 添加通过引导实践教授 OpenSpec workflow 的 `/opsx:onboard` skill
- 遵循现有的 skill/命令 template 生成 schema
- 提供解释每个步骤的综合解说
- 包含代码分析以建议真实的、范围适中的任务

**非目标：**
- 创建单独的"演示 schema"或模拟 workflow（我们做真实工作）
- 添加新的 CLI 命令（这纯粹是 agent 指令）
- 修改 init/update 流程（仅添加到 template 数组）

## 决策

### 决策 1：单一整体 skill

入门 skill 将是一个单一的综合指令集，而不是用标志组合现有 skill。

**理由：**
- 斜杠命令不支持标志（它们只是提示）
- 整体 skill 可以完全控制解说和节奏
- 保持单一连贯的体验更易于维护
- 用户通过在解说中看到真实命令来学习它们

### 决策 2：代码分析 schema

skill 指令将指导 agent 在建议入门级任务时寻找特定 schema：

1. 代码中的 TODO/FIXME 注释
2. 缺失的错误处理（吞没错误的 `catch` 块，危险操作周围没有 try-catch）
3. 没有测试的函数（将 src/ 与测试文件交叉引用）
4. TypeScript 文件中的 type: any
5. 非调试代码中的 console.log 语句
6. 面向用户输入上的缺失输入验证
7. 最近的 git 提交（了解用户正在处理的内容的上下文）

**理由：** 这些是普遍适用、易于检测并能产生范围良好的任务。

### 决策 3：解说集成风格

每个阶段将遵循一个 schema：
1. **解释** 我们将要做什么以及为什么（1-2 句话）
2. **执行** 操作（运行命令、创建 artifact）
3. **展示** 发生了什么
4. **暂停** 在关键过渡点（不是每一步）

暂停发生在：
- 任务选择后（创建变更前）
- 起草 proposal 后（保存前）
- 任务生成后（实现前）
- archive 后（最终回顾）

**理由：** 暂停太多变得乏味。太少则失去教学机会。这些是自然的"章节分隔。"

### 决策 4：范围防护方法

当用户选择的任务太大时，skill 将：
1. 承认该任务有价值
2. 解释为什么第一次做小一点的更好
3. 建议较小的切片或替代方案
4. 如果用户坚持，允许覆盖

**理由：** 软性防护在不让人沮丧的情况下进行教学。用户在此体验中学习范围校准。

### 决策 5：template 结构

skill template 将包含约 400-600 行的指令文本，结构如下：

```
- 预检检查（init 状态）
- 阶段 1：欢迎与设置
- 阶段 2：任务选择（包含代码分析指令）
- 阶段 3：探索演示（简短）
- 阶段 4：变更创建
- 阶段 5：proposal
- 阶段 6：spec
- 阶段 7：设计
- 阶段 8：任务
- 阶段 9：应用（实现）
- 阶段 10：archive
- 阶段 11：回顾与后续步骤
- 边界情况与优雅退出
```

命令 template 将与 skill template 相同（相同内容，不同包装器）。

**理由：** 遵循已建立的 schema，即 skill 和命令共享相同的核心指令。

## 风险 / 权衡

**风险：指令长度**
该 skill 将比其他现有 skill 长得多（约 500 行 vs 约 100-200 行）。
→ 缓解措施：这是可以接受的，因为入门本质上是全面的。令牌成本是每次会话一次的。

**风险：代码分析可能找不到任何内容**
某些代码库（新项目、非常干净的代码）可能没有明显的改进机会。
→ 缓解措施：回退到询问用户想要构建什么。将"添加新功能"作为选项包含。

**风险：任务建议可能不合适**
agent 可能建议触及敏感代码或具有隐藏复杂性的任务。
→ 缓解措施：用户总是选择；agent 仅建议。范围估算有助于设定预期。

**风险：用户中途放弃**
入门大约需要 15 分钟；用户可能不会完成。
→ 缓解措施：优雅退出处理——注明变更是保存的，解释以后如何继续。
