# 规范：规则注入

## 新增的需求

### 需求：仅对匹配的工件注入规则

系统应仅在工件 ID 匹配规则对象中的键时，将配置中的规则注入到指令中。

#### 场景：规则存在于工件中
- **当** 加载 "proposal" 的指令且配置包含 `rules: { proposal: ["规则 1", "规则 2"] }`
- **则** 指令输出包含两条规则的 rules 章节

#### 场景：工件没有规则
- **当** 加载 "design" 的指令且配置包含 `rules: { proposal: [...] }`
- **则** 指令输出不包含 `<rules>` 标签

#### 场景：规则对象未定义
- **当** 配置省略了 rules 字段或 rules 未定义
- **则** 任何工件的指令输出都不包含 `<rules>` 标签

#### 场景：工件的规则数组为空
- **当** 配置包含 `rules: { proposal: [] }`
- **则** 指令输出不包含 `<rules>` 标签

### 需求：使用 XML 风格标签和项目符号列表格式化规则

系统应将规则包裹在 `<rules>` 标签中，每条规则作为项目符号列表项。

#### 场景：工件单条规则
- **当** 配置包含 `rules: { proposal: ["包含回滚计划"] }`
- **则** 指令输出包含 `<rules>\n- 包含回滚计划\n</rules>\n\n`

#### 场景：工件多条规则
- **当** 配置包含 `rules: { proposal: ["规则 1", "规则 2", "规则 3"] }`
- **则** 指令输出将每条规则作为单独的项目符号点

#### 场景：规则出现在上下文之后、模板之前
- **当** 生成同时包含上下文和规则的指令时
- **则** 顺序为 `<context>` 然后 `<rules>` 然后 `<template>`

### 需求：保留规则文本原样

系统应注入规则文本而不进行修改、转义或解释。

#### 场景：规则包含 Markdown
- **当** 规则包含如 "使用 **Given/When/Then** 格式" 的 Markdown
- **则** Markdown 在注入内容中保留

#### 场景：规则包含特殊字符
- **当** 规则包含如 `<`、`>`、引号等字符
- **则** 字符按原样保留

#### 场景：规则是多行字符串
- **当** 规则文本包含换行符
- **则** 项目符号点内保留换行符

### 需求：支持不同规则的多工件

系统应允许在同一配置中为不同工件设置不同的规则集。

#### 场景：多个工件有规则
- **当** 配置包含 `rules: { proposal: ["P1"], specs: ["S1", "S2"], tasks: ["T1"] }`
- **则** proposal 指令仅显示 ["P1"]，specs 仅显示 ["S1", "S2"]，tasks 仅显示 ["T1"]

#### 场景：部分工件有规则，部分没有
- **当** 配置仅为 proposal 和 specs 设置了规则
- **则** design 和 tasks 指令没有 `<rules>` 章节

### 需求：规则是对模式指导的补充

系统应将配置规则添加到模式内置的工件指令中，而非替换它。

#### 场景：工件有模式指令和配置规则
- **当** 工件有来自模式的内置指令且配置提供了规则
- **则** 最终指令包含模式指导和配置规则

#### 场景：规则提供额外约束
- **当** 模式说"创建提案"且配置规则说"包含回滚计划"
- **则** 代理同时看到模式模板和额外规则

### 需求：在加载指令时验证工件 ID

系统应在加载指令时验证规则中的工件 ID 是否与模式匹配，并为未知 ID 发出警告。

#### 场景：所有工件 ID 有效
- **当** 指令已加载且配置对包含这些工件的模式设置了 `rules: { proposal: [...], specs: [...] }`
- **则** 不发出验证警告

#### 场景：规则中存在未知工件 ID
- **当** 指令已加载且配置包含 `rules: { unknownartifact: [...] }`
- **则** 发出警告："规则中存在未知工件 ID：'unknownartifact'。模式 'spec-driven' 的有效 ID：design、proposal、specs、tasks"

#### 场景：多个未知工件 ID
- **当** 指令已加载且配置包含多个未知工件 ID
- **则** 为每个未知工件 ID 分别发出警告

#### 场景：每个会话仅显示一次验证警告
- **当** 在同一个 CLI 会话中多次加载指令
- **则** 每个唯一的验证警告仅显示一次（缓存）
