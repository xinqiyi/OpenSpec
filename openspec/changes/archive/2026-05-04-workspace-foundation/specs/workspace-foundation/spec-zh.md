## 新增需求

### 需求：可识别的工作区中心
OpenSpec 应为用户和代理提供一个可识别的工作区中心，用于跨仓库规划。

#### 场景：跨链接仓库或文件夹进行规划
- **WHEN** 用户为其规划的仓库或文件夹创建 OpenSpec 工作区
- **THEN** 工作区应提供一个持久化的规划中心
- **AND** 工作区应能够随时间持有多个变更

#### 场景：从工作区内部工作
- **GIVEN** 用户从工作区根目录或其子目录之一运行 OpenSpec
- **WHEN** OpenSpec 解析当前工作区
- **THEN** 它应识别工作区根目录
- **AND** 它应使用工作区根目录的 `changes/` 目录作为工作区规划区域

#### 场景：避免意外的工作区模式
- **GIVEN** 一个目录有 `changes/` 但不是一个 OpenSpec 工作区
- **WHEN** OpenSpec 解析当前工作区
- **THEN** 它应避免将该目录视为工作区
- **AND** 仅当工作区标识文件存在时才进入工作区模式

### 需求：稳定的工作区名称
OpenSpec 应在工作区标识、托管存储和本地注册表中使用一个文件夹风格的工作区名称。

#### 场景：使用一个工作区名称
- **WHEN** OpenSpec 创建或注册一个托管工作区
- **THEN** 工作区名称应存储在 `.openspec-workspace/workspace.yaml` 中
- **AND** 相同的名称应作为默认的托管工作区文件夹名称
- **AND** 相同的名称应作为本地注册表名称

#### 场景：拒绝无效的文件夹风格名称
- **WHEN** OpenSpec 接受一个工作区名称
- **THEN** 它应拒绝空名称、`.` 或 `..`，以及包含路径分隔符的名称
- **AND** setup 或 create 流程应清晰地报告操作系统级别的文件夹创建失败

### 需求：专用工作区标识
OpenSpec 应区分协调工作区和仓库本地的 OpenSpec 项目。

#### 场景：读取工作区标识
- **WHEN** OpenSpec 读取或写入工作区标识和工作区状态
- **THEN** 它应使用 `.openspec-workspace/`

#### 场景：保留仓库本地的 OpenSpec 项目
- **GIVEN** 仓库本地的 OpenSpec 项目使用 `openspec/`
- **WHEN** 该仓库被链接到一个工作区
- **THEN** OpenSpec 应继续将 `openspec/` 视为该仓库的本地 OpenSpec 目录
- **AND** 工作区规划应保持锚定在工作区根目录

#### 场景：避免在工作区根目录进行仓库本地初始化
- **WHEN** 用户从 OpenSpec 工作区根目录工作
- **THEN** OpenSpec 应将该根目录视为工作区协调界面
- **AND** 用户无需在工作区根目录内初始化仓库本地的 `openspec/` 项目

### 需求：安全的工作区共享
OpenSpec 应将共享工作区信息与本地机器路径分开保存。

#### 场景：共享工作区规划
- **WHEN** 工作区与另一个用户或机器共享
- **THEN** 共享工作区信息应包括可移植的工作区标识和稳定的链接名称
- **AND** 不应要求其他用户重用原始用户的绝对检出路径

#### 场景：保持检出路径本地化
- **WHEN** OpenSpec 存储工作区的本地路径
- **THEN** 这些路径应被视为当前机器和运行时的本地路径
- **AND** 另一台机器可以将相同的链接名称映射到不同的本地路径

#### 场景：保留运行时本地路径
- **WHEN** OpenSpec 读取或写入本地工作区路径
- **THEN** 它应保留对当前运行时有效的路径字符串
- **AND** 它应支持原生 Windows 路径和 WSL2/Linux 路径作为本地状态值

#### 场景：从可移植协作中排除本地状态
- **WHEN** OpenSpec 创建一个工作区
- **THEN** 它应默认从可移植协作状态中排除 `.openspec-workspace/local.yaml`
- **AND** `.openspec-workspace/workspace.yaml` 应保持为可移植的工作区标识和链接名称状态

### 需求：标准工作区位置
OpenSpec 应使用标准位置存储 OpenSpec 托管的工作区，无需大多数用户自行选择。

#### 场景：使用标准工作区位置
- **WHEN** OpenSpec 需要 OpenSpec 托管工作区的位置
- **THEN** 它应使用 `<global-data-dir>/workspaces`
- **AND** `<global-data-dir>` 应遵循现有的 OpenSpec XDG 和平台数据目录行为

#### 场景：避免工作区特定的存储覆盖
- **WHEN** OpenSpec 解析 OpenSpec 托管工作区的位置
- **THEN** 在此切片中，它不应使用工作区特定的环境变量、命令或配置设置
- **AND** 托管工作区存储应保持在 `<global-data-dir>/workspaces` 下

#### 场景：从原生 Windows 运行
- **WHEN** OpenSpec 从原生 Windows shell（如 PowerShell）运行
- **AND** 未设置 `XDG_DATA_HOME`
- **THEN** OpenSpec 应将托管工作区存储在 Windows 全局数据位置下
- **AND** 路径应遵循原生 Windows 路径行为

#### 场景：从 WSL2 运行
- **WHEN** OpenSpec 从 WSL2 运行
- **THEN** OpenSpec 应将托管工作区存储在 WSL 内的 Linux/XDG 数据位置下
- **AND** WSL 内的路径应遵循 Linux 路径行为

#### 场景：自动使用工作区位置
- **WHEN** OpenSpec 在后续工作流中创建或解析 OpenSpec 托管工作区
- **THEN** 它应默认使用已解析的工作区位置
- **AND** 用户应能够遵循正常的工作区流程而无需选择存储位置

#### 场景：显示工作区路径
- **WHEN** OpenSpec 在标准工作区位置创建一个工作区
- **THEN** 它应向用户报告工作区路径
- **AND** 它不应隐藏规划文件的创建位置

#### 场景：保持在当前运行时
- **WHEN** OpenSpec 解析工作区路径或本地仓库路径
- **THEN** 它应为运行 OpenSpec 的运行时解释路径
- **AND** Windows、UNC WSL 和 WSL 挂载路径应保持为显式用户提供的路径

### 需求：本地工作区注册表
OpenSpec 应在当前机器上维护一个轻量级的已知工作区本地注册表。

#### 场景：记录已知工作区
- **WHEN** OpenSpec 创建或了解到一个托管工作区
- **THEN** 它应能够将工作区名称和路径记录在本地注册表中
- **AND** 注册表应是机器本地状态

#### 场景：保持工作区文件夹的权威性
- **WHEN** OpenSpec 读取工作区详细信息
- **THEN** 每个工作区文件夹的 `.openspec-workspace/workspace.yaml` 应保持为该工作区的真相来源
- **AND** 本地注册表应仅作为已知工作区路径的索引

#### 场景：从任何位置查找工作区
- **WHEN** 后续工作区命令在工作区目录外部运行
- **THEN** OpenSpec 可以使用本地注册表查找已知工作区
- **AND** 需要一个工作区的命令可以使用注册表来支持交互式选择器

### 需求：稳定的链接名称
OpenSpec 应使用稳定的链接名称在工作区规划中引用仓库和文件夹。

#### 场景：在工作区规划中引用仓库或文件夹
- **WHEN** 工作区状态或后续工作区规划工件引用链接的仓库或文件夹
- **THEN** 它们应使用稳定的链接名称
- **AND** 即使本地检出路径不同，相同的链接名称也应保持有效

#### 场景：跨机器重用链接名称
- **WHEN** 工作区在另一台机器上使用
- **THEN** 链接名称应保持稳定
- **AND** 该机器上的本地检出路径可能不同

#### 场景：拒绝无效的链接名称
- **WHEN** OpenSpec 接受一个工作区链接名称
- **THEN** 它应拒绝空名称、`.` 或 `..`，以及包含路径分隔符的名称
- **AND** 链接名称在工作区内应是唯一的

### 需求：链接的仓库和文件夹
OpenSpec 应允许工作区规划在链接的仓库和文件夹具有仓库本地 OpenSpec 状态之前就包含它们。

#### 场景：规划尚未采用 OpenSpec 的仓库
- **WHEN** 工作区链接了一个尚未包含仓库本地 `openspec/` 的仓库路径
- **THEN** 该仓库仍应可用于工作区级别的规划
- **AND** 实现就绪性可由后续工作流处理

#### 场景：跨单仓库文件夹进行规划
- **WHEN** 规划跨越一个单仓库内的多个包、服务、应用或目录
- **THEN** 工作区应能够分别链接这些文件夹
- **AND** 每个文件夹无需拥有自己的仓库本地 `openspec/` 目录即可参与工作区规划

#### 场景：一致对待仓库和文件夹
- **WHEN** 工作区计划同时包含单独的仓库和单仓库内的文件夹
- **THEN** OpenSpec 应对两者使用相同的规划模型
- **AND** 用户无需为多仓库和单仓库变更创建不同类型的工作区计划

#### 场景：记录链接而不修改目标
- **WHEN** OpenSpec 记录工作区与本地仓库或文件夹之间的链接
- **THEN** 它应将链接存储在工作区状态中
- **AND** 它不应在链接的仓库或文件夹内创建、复制、移动、初始化或编辑文件

### 需求：先规划后实现
OpenSpec 应将工作区创建和检测视为规划设置，而非实现。

#### 场景：创建或检测工作区
- **WHEN** 工作区存在
- **THEN** OpenSpec 应将其视为工作区级规划的地方
- **AND** 仓库实现文件应保持不变，直到显式的实现工作流运行

#### 场景：推迟仓库实现
- **WHEN** 需要仓库本地的实现、应用、验证或归档行为
- **THEN** 该行为需要显式的后续工作区工作流

### 需求：仓库所有权边界
当在工作区中进行规划时，OpenSpec 应保持仓库所有权清晰可读。

#### 场景：跨所属仓库进行规划
- **WHEN** 工作区计划引用属于某个仓库或源代码区域的行为
- **THEN** 该所有者应仍然是规范规格和实现工作的归属地
- **AND** 工作区应使跨边界计划可见，而不从该所有者处夺取所有权

#### 场景：在所有权明确之前进行草稿
- **WHEN** 跨仓库行为仍在探索中，所有权不明确
- **THEN** 工作区可以持有规划说明或草稿行为
- **AND** 这些草稿应保持与规范的仓库所属规格可区分
