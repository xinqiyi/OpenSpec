## 修改后的需求

### 需求：稳定的工作区名称
OpenSpec 应使用一个 kebab-case 的工作区名称，贯穿工作区标识、托管存储和本地注册表。

#### 场景：使用统一的工作区名称
- **当** OpenSpec 创建或记录托管工作区时
- **则** 工作区名称应存储在 `.openspec-workspace/workspace.yaml` 中
- **并且** 同一名称应作为默认的托管工作区文件夹名称
- **并且** 同一名称应作为本地注册表名称

#### 场景：拒绝无效的工作区名称
- **当** OpenSpec 接受工作区名称时
- **则** 应要求使用 kebab-case 命名，仅限小写字母、数字和单个连字符分隔符
- **并且** 应拒绝空名称、点名称、以连字符开头或结尾的名称、重复连字符、大写字母、空格、下划线、点和路径分隔符
- **并且** 设置流程应清晰报告操作系统级别的文件夹创建失败

### 需求：稳定的链接名称
OpenSpec 应使用稳定的文件夹式链接名称来引用工作区规划中的仓库和文件夹。

#### 场景：在工作区规划中引用仓库或文件夹
- **当** 工作区状态或后续工作区规划工件引用已链接的仓库或文件夹时
- **则** 应使用稳定的链接名称
- **并且** 即使本地检出路径不同，同一链接名称仍应保持有效

#### 场景：跨机器复用链接名称
- **当** 工作区在另一台机器上使用时
- **则** 链接名称应保持稳定
- **并且** 该机器上的本地检出路径可以不同

#### 场景：拒绝无效的链接名称
- **当** OpenSpec 接受工作区链接名称时
- **则** 应拒绝空名称、`.` 或 `..`，以及包含路径分隔符的名称
- **并且** 链接名称应在工作区内唯一
- **并且** 链接名称不要求使用工作区名称的 kebab-case 格式
