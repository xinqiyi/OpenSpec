## 新增需求

### 需求：工作区规划模式
工件图应提供一个内置的工作区规划模式，用于工作区范围的变更。

#### 场景：内置的工作区规划模式可用
- **当** 从包内置项解析模式时
- **则** 应提供一个名为 `workspace-planning` 的模式
- **并且** 它应描述工作区范围规划的工件结构

#### 场景：工作区规划模式工件
- **当** 加载 `workspace-planning` 模式时
- **则** 它应包括共享提案、工作区范围规格、跨区域设计和协调任务等标准规划工件
- **并且** 在这些标准规划工件之外，不应再要求额外的区域清单

#### 场景：工作区规划模式支持嵌套规格
- **当** `workspace-planning` 模式定义其规格工件时
- **则** 规格工件应解析 `specs/**/*.md` 下的工作区范围规格文件
- **并且** 模式指引应将 `specs/<区域或仓库>/<能力>/spec.md` 描述为按区域组织需求的默认约定

#### 场景：工作区规划模式模板
- **当** 请求 `workspace-planning` 模式的工件指令时
- **则** 模式应提供指导代理编写工作区级别规划内容的模板
- **并且** 这些模板应避免指示代理创建仓库本地的实施工件
- **并且** 规格指令应支持在工作区范围的 `specs/` 路径下组织特定区域的需求

#### 场景：工作区嵌套规格路径保持工作区范围
- **给定** 工作区变更有位于 `specs/<区域或仓库>/<能力>/spec.md` 下的规格文件
- **当** OpenSpec 报告工作区变更的状态或工件指令时
- **则** 应保留具体的嵌套工作区规格路径
- **并且** 除非有明确的影响区域实施上下文，否则不应将这些文件视为需要同步或归档的仓库本地规格

#### 场景：工作区规划应用就绪状态
- **当** `workspace-planning` 模式定义应用就绪状态时
- **则** 在开始实施之前应要求完成协调任务
- **并且** 应用指引应指导代理在做出实施编辑之前先选择影响区域
