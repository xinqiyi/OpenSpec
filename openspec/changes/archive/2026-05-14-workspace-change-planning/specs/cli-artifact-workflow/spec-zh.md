## 新增的需求

### 需求：状态 JSON 提供规划上下文

status 命令应为仓库本地和工作区变更提供机器可读的规划上下文。

#### 场景：报告规划归属
- **当** 用户运行 `openspec status --change <id> --json`
- **则** 输出应标识变更是仓库本地还是工作区范围
- **并且** 应包含规划归属根路径和变更根路径

#### 场景：报告具体工件路径
- **当** 用户运行 `openspec status --change <id> --json`
- **则** 输出应包含现有工件的具体路径
- **并且** 代理应能读取这些路径，无需假设 `openspec/changes/<id>/`
- **并且** 工作区范围的嵌套规范路径应在不展平区域或能力路径的情况下报告

#### 场景：报告工作区受影响区域
- **给定** 变更属于工作区范围
- **当** 用户运行 `openspec status --change <id> --json`
- **则** 输出应包含已知的受影响区域
- **并且** 应在无需额外区域清单工件的情况下，指示受影响区域尚未解决

#### 场景：报告后续步骤
- **当** 用户运行 `openspec status --change <id> --json`
- **则** 输出应包含代理的后续步骤指导
- **并且** 指导应使用简洁的行动语言

### 需求：状态 JSON 行动上下文

status 命令应暴露行动上下文，使代理无需硬编码的文件系统假设即可行动。

#### 场景：规划行动上下文
- **当** 工作区变更仍处于规划阶段
- **则** 状态 JSON 应标识代理可以读取或更新的规划工件
- **并且** 应指示链接的仓库和文件夹是供探索的上下文

#### 场景：实施行动上下文
- **当** 工作区变更有选定的受影响区域进行实施
- **则** 状态 JSON 应包含该区域的允许编辑根路径
- **并且** 应避免授权对选定区域之外的编辑

#### 场景：仓库本地行动上下文
- **给定** 变更是仓库本地的
- **当** 用户运行 `openspec status --change <id> --json`
- **则** 状态 JSON 应保留现有工件状态行为
- **并且** 应为使用行动上下文的代理报告仓库本地规划归属

### 需求：指令使用解析后的规划路径

工件和应用指令应使用解析后的规划路径，而非硬编码的仓库本地变更路径。

#### 场景：工作区工件指令
- **给定** 变更属于工作区范围
- **当** 用户运行 `openspec instructions <artifact> --change <id> --json`
- **则** 指令输出应指向工作区变更根路径下的工件路径
- **并且** 不应指示代理写入链接的仓库，除非有明确的实施上下文允许

#### 场景：仓库本地工件指令
- **给定** 变更是仓库本地的
- **当** 用户运行 `openspec instructions <artifact> --change <id> --json`
- **则** 指令输出应保留现有的仓库本地路径

### 需求：工作流技能使用 CLI 工件上下文

生成的工作流技能应使用 OpenSpec CLI 输出作为工件位置的真实来源。

#### 场景：技能在工件工作前检查状态
- **当** 生成的工作流技能需要检查或创建变更的工件时
- **则** 应指示代理运行 `openspec status --change <id> --json`
- **并且** 应使用返回的规划上下文和工件路径，而非假设仓库本地变更路径

#### 场景：技能在写入工件前使用指令
- **当** 生成的工作流技能即将创建或更新工件时
- **则** 应指示代理运行 `openspec instructions <artifact> --change <id> --json`
- **并且** 应写入命令返回的已解析工件路径

#### 场景：技能避免硬编码的仓库本地路径
- **当** 生成的工作流技能描述工件位置时
- **则** 应避免要求变更位于 `openspec/changes/<id>/` 下的硬编码示例
- **并且** 任何示例都应参考 CLI 报告的路径，无论是仓库本地还是工作区范围变更

#### 场景：技能保护不支持的工作区工作流
- **给定** 生成的工作流技能被全局配置文件选中
- **并且** 该工作流在此切片中尚未具备完整的工作区范围行为
- **当** 该技能用于工作区范围变更时
- **则** 应告知代理该工作区操作尚不支持
- **并且** 不应指示代理回退到仓库本地路径或在没有明确允许编辑根路径的情况下编辑链接的仓库

### 需求：工作区模式指令

工作流命令应为使用工作区规划模式的工作区范围变更使用工作区规划模式指令。

#### 场景：工作区规划工件顺序
- **给定** 工作区范围变更使用模式 `workspace-planning`
- **当** 用户运行 `openspec status --change <id> --json`
- **则** 工件列表应反映工作区规划模式
- **并且** 应包括正常的提案、规范、设计和任务工件

#### 场景：工作区规范指令
- **给定** 工作区范围变更使用模式 `workspace-planning`
- **当** 用户请求规范工件的指令时
- **则** 指令输出应引导代理在工作区范围的 `specs/` 路径下组织特定区域的需求
- **并且** 不应要求所有受影响区域都确定后才能继续规划
- **并且** 不应指示代理在变更仍处于工作区规划阶段时创建仓库本地规范文件
