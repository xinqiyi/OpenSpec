## 新增需求

### 需求：工作区规划词汇
OpenSpec 约定应使用面向用户的产品语言来区分工作区规划概念。

#### 场景：命名影响区域
- **当** 文档或生成的指引提及工作区变更涉及的仓库、文件夹、包、服务、应用或文档站点时
- **则** 应将其称为影响区域
- **并且** 应避免使用"目标仓库"或"仓库切片"作为主要面向用户的术语

#### 场景：命名交付切片
- **当** 文档或生成的指引提及较大变更内部的交付增量时
- **则** 仅在交付排序是主题时才应将其称为切片或阶段
- **并且** 不应将切片用作仓库、文件夹或影响区域的同义词

### 需求：工作区规划与实施的边界
OpenSpec 约定应区分工作区级别的规划与仓库本地的实施所有权。

#### 场景：工作区作为共享规划中心
- **当** 变更跨越已链接的仓库或文件夹时
- **则** 约定应将工作区描述为共享规划中心
- **并且** 仓库本地的实施中心应保留对其代码和规范行为的所有权

#### 场景：避免以物化优先的语言表达
- **当** 文档解释工作区变更创建时
- **则** 应从共享规划和影响区域的角度描述用户成果
- **并且** 应避免让用户在能够规划之前就需要理解诸如物化等实施术语

#### 场景：保留熟悉的工作流动词
- **当** 工作区指引描述 OpenSpec 工作流时
- **则** 应保留熟悉的动词：探索、提议、应用、验证和归档
- **并且** 应解释工作区上下文改变了路径、范围和允许的编辑根目录，而不是创建了一个独立的工作流体系
