## 新增需求

### 需求：工作区规划模式解析
模式解析应支持内置的工作区规划模式。

#### 场景：列出工作区规划模式
- **当** 用户运行 `openspec schemas` 时
- **则** 输出应包含 `workspace-planning`
- **并且** 除非被更高优先级的模式覆盖，否则应将其标识为包提供的模式

#### 场景：按名称解析工作区规划模式
- **当** 工作流命令请求 `workspace-planning` 模式时
- **则** 模式解析应按照正常的项目、用户再到包的优先级顺序进行解析

#### 场景：新变更的默认工作区模式
- **给定** 命令在工作区规划中心创建变更
- **并且** 用户未传递显式的 `--schema`
- **当** OpenSpec 为新变更解析模式时
- **则** 应使用 `workspace-planning` 作为默认模式

#### 场景：工作区变更的显式模式覆盖
- **给定** 命令在工作区规划中心创建变更
- **当** 用户传递显式的 `--schema <名称>` 时
- **则** OpenSpec 应使用显式请求的模式
- **并且** 应使用正常的模式解析来验证该模式
