## 目的

update 命令应将全局配置变更应用到已有项目，同步配置文件和交付偏好，而无需完全重新初始化。

## 被修改的需求

### 需求：Update 遵循全局 profile 配置
update 命令应读取全局配置并将 profile 设置应用到项目。

#### 场景：Update 从配置中添加缺失的工作流
- **当** 用户运行 `openspec update`
- **且** 全局配置指定了当前未安装在项目中的工作流
- **则** 系统应为缺失的工作流生成技能/命令文件
- **则** 系统应显示："已添加：<工作流名称>"

#### 场景：Update 刷新已有工作流
- **当** 用户运行 `openspec update`
- **且** 工作流已安装在项目中
- **则** 系统应使用最新模板刷新那些工作流文件
- **则** 系统应显示："已更新：<工作流名称>"

#### 场景：无需变更的 Update
- **当** 用户运行 `openspec update`
- **且** 已安装的工作流与全局配置匹配
- **且** 所有模板都是最新的
- **且** 交付设置与已安装文件匹配
- **则** 系统应显示："已是最新。"

#### 场景：Profile 或交付与当前模板不一致
- **当** 用户运行 `openspec update`
- **且** 已安装技能的工作流模板是最新的
- **且** 项目文件与当前 profile 和/或交付配置不匹配
- **则** 系统应将其视为需要更新的状态（而非"已是最新。"）
- **则** 系统应添加/删除文件以匹配当前的 profile 和交付设置

#### 场景：Update 汇总输出
- **当** update 完成并有变更
- **则** 系统应显示汇总：
  - "已添加：propose, explore"（新安装的工作流）
  - "已更新：apply, archive"（已刷新的现有工作流）
  - "已移除：4 个命令文件"（如果交付方式变更）
- **则** 系统应列出受影响的工具："工具：Claude Code, Cursor"

### 需求：Update 遵循交付设置
update 命令应根据交付设置添加或删除文件。

#### 场景：交付方式变更为仅技能
- **当** 用户运行 `openspec update`
- **且** 全局配置指定 `delivery: skills`
- **且** 项目已安装命令文件
- **则** 系统应删除 profile 中工作流的命令文件
- **则** 系统应仅生成/更新技能文件
- **则** 系统应显示："已移除：<数量> 个命令文件（交付方式：skills）"

#### 场景：交付方式变更为仅命令
- **当** 用户运行 `openspec update`
- **且** 全局配置指定 `delivery: commands`
- **且** 项目已安装技能文件
- **则** 系统应删除 profile 中工作流的技能目录
- **则** 系统应仅生成/更新命令文件
- **则** 系统应显示："已移除：<数量> 个技能目录（交付方式：commands）"

#### 场景：交付方式为两者
- **当** 用户运行 `openspec update`
- **且** 全局配置指定 `delivery: both`
- **则** 系统应生成/更新技能和命令文件

### 需求：Update 检测已配置的工具（来自技能或命令）
update 命令应将拥有生成的技能文件或命令文件的工具视为已配置。

#### 场景：仅命令安装
- **当** 用户运行 `openspec update`
- **且** 某个工具拥有生成的 OpenSpec 命令文件
- **且** 该工具没有 OpenSpec 技能文件（仅命令交付）
- **则** 该工具仍应被视为已配置
- **则** 系统应对该工具应用 profile 和交付同步

### 需求：针对现有用户的一次性迁移
update 命令应检测现有用户（全局配置中无 `profile` + 存在现有工作流）并在应用更新前将其迁移到 `custom` profile。

#### 场景：升级后首次 update（现有用户）
- **当** 用户运行 `openspec update`
- **且** 全局配置不包含 `profile` 字段
- **且** 项目已有工作流文件安装
- **则** 系统应扫描项目中所有工具目录下的已安装工作流
- **则** 系统应仅匹配 `ALL_WORKFLOWS` 常量中存在的工作流名称（忽略用户创建的自定义技能）
- **则** 系统应取所有工具检测到的工作流名称的并集
- **则** 系统应写入全局配置：`profile: "custom"`、`delivery: "both"`、`workflows: [<检测到的工作流>]`
- **则** 系统应显示："已迁移：包含 <数量> 个工作流的自定义 profile（<工作流名称>）"
- **则** 系统应显示："此版本新增：/opsx:propose（合并了 new + ff）。尝试 'openspec config profile core' 体验精简的 4 工作流模式。"
- **则** 系统应继续执行正常的 update 逻辑（使用迁移后的配置）
- **则** 结果应仅为模板刷新（无工作流添加或移除）

#### 场景：部分工作流的迁移（用户手动移除了一些）
- **当** 用户运行 `openspec update`
- **且** 全局配置不包含 `profile` 字段
- **且** 项目安装的工作流少于原始的 10 个
- **则** 系统应仅迁移实际存在的工作流
- **则** 迁移后的 `workflows` 数组应反映用户的当前状态，而非原始集合

#### 场景：多工具具有不同工作流集合的迁移
- **当** 用户运行 `openspec update`
- **且** 项目配置了多个工具（例如 Claude Code, Cursor）
- **且** 不同工具安装了不同的工作流
- **则** 系统应取所有工具检测到的工作流的并集
- **则** 迁移后的 `workflows` 数组应包含至少在一个工具中存在的所有工作流

#### 场景：无需迁移（profile 已设置）
- **当** 用户运行 `openspec update`
- **且** 全局配置已包含 `profile` 字段
- **则** 系统不应执行迁移
- **则** 系统应使用现有配置继续执行正常的 update 逻辑

#### 场景：无需迁移（无现有工作流）
- **当** 用户运行 `openspec update`
- **且** 全局配置不包含 `profile` 字段
- **且** 项目没有现有工作流文件
- **则** 系统不应执行迁移
- **则** 系统应使用 `core` profile 的默认值

#### 场景：迁移是幂等的
- **当** 用户多次运行 `openspec update`
- **则** 迁移应仅在首次运行时发生（当 `profile` 字段不存在时）
- **则** 后续运行应使用现有的全局配置，无需重新扫描

#### 场景：非交互式迁移
- **当** 用户以非交互方式运行 `openspec update`（例如在 CI 中）
- **且** 触发了迁移
- **则** 系统应在不提示的情况下执行迁移
- **则** 系统应将迁移摘要输出到 stdout

### 需求：Update 检测新的工具目录
update 命令应在检测到当前未配置的新 AI 工具目录时通知用户。

#### 场景：检测到新工具目录
- **当** 用户运行 `openspec update`
- **且** 检测到新的工具目录（例如 `.windsurf/` 存在但 Windsurf 未配置）
- **则** 系统应显示："检测到新工具：Windsurf。运行 'openspec init' 以添加。"
- **则** 系统不应自动添加新工具
- **则** 系统应仅为当前已配置的工具继续执行 update

#### 场景：检测到多个新工具目录
- **当** 用户运行 `openspec update`
- **且** 检测到多个新工具目录（例如 `.github/` 和 `.windsurf/` 都存在但均未配置）
- **则** 系统应显示一条整合消息，列出所有检测到的工具，例如："检测到新工具：GitHub Copilot, Windsurf。运行 'openspec init' 以添加。"
- **则** 系统不应自动添加任何新工具
- **则** 系统应仅为当前已配置的工具继续执行 update

#### 场景：没有新工具目录
- **当** 用户运行 `openspec update`
- **且** 未检测到新工具目录
- **则** 系统不应显示任何工具检测消息

### 需求：Update 需要 OpenSpec 项目
update 命令只能在已初始化的 OpenSpec 项目中运行。

#### 场景：在项目外执行 Update
- **当** 用户运行 `openspec update`
- **且** 当前工作目录中不存在 `openspec/` 目录
- **则** 系统应显示："未找到 OpenSpec 项目。运行 'openspec init' 进行设置。"
- **则** 系统应以退出码 1 退出

### 需求：额外工作流同步到活跃 profile
update 命令应移除当前 profile 中不再选中的工作流文件。

#### 场景：从之前的 profile 中取消选择的工作流
- **当** 用户运行 `openspec update`
- **且** 项目包含不在当前 profile 中的工作流（例如用户从 custom 切换到 core，或通过 `openspec config profile` 取消选择了工作流）
- **则** 系统应为取消选择的工作流删除技能和命令工作流文件（尊重当前的交付模式）
- **则** 系统应仅保留当前 profile 中选中的工作流

#### 场景：伴有额外工作流的交付方式变更
- **当** 用户运行 `openspec update`
- **且** 交付方式已变更（例如 `both` → `skills`）
- **且** 项目包含不在当前 profile 中的额外工作流
- **则** 系统应删除匹配已移除交付类型的额外工作流的文件
- **则** 例如：如果切换到 `skills`，所有命令文件都被删除（包括额外工作流的）
