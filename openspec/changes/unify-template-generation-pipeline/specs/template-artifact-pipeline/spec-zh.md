# template-artifact-pipeline 规范

## 目的

定义一个统一的工作流模板生成架构，集中管理工作流定义、工具能力连接、转换执行和工件同步，同时保持输出保真度。

## 新增的需求

### 需求：规范工作流清单

系统应将规范工作流清单定义为生成的技能和命令工件的唯一真实来源。

#### 场景：一次性注册工作流

- **当** 添加或修改工作流（例如 `explore`、`ff` 或 `onboard`）时
- **则** 其规范定义应在工作流清单中一次性注册
- **并且** 技能/命令投影应从该清单派生
- **并且** 不应需要重复维护的列表

#### 场景：必需的技能元数据

- **当** 在清单中定义工作流技能条目时
- **则** 应包含必需的元数据字段（`license`、`compatibility` 和 `metadata`）
- **并且** 生成应使用这些值或对所有工作流以一致的方式使用显式默认值

### 需求：工具配置文件注册表

系统应定义一个工具配置文件注册表，捕获每个工具的生成能力。

#### 场景：解析工具能力

- **当** 为所选工具生成工件时
- **则** 系统应解析声明技能路径能力、命令适配器连接和转换集的工具配置文件
- **并且** 支持技能但没有命令适配器的工具应被显式处理，无隐式回退行为

#### 场景：能力一致性验证

- **当** 运行验证检查时
- **则** 系统应检测已配置工具、配置文件定义和已注册适配器之间的不匹配
- **并且** 在开发/CI 中以可操作的错误失败

### 需求：有序转换流水线

系统应支持具有显式范围和阶段语义的有序工件转换。

#### 场景：执行适配器前和适配器后转换

- **当** 生成工件时
- **则** 匹配的转换应基于阶段和优先级按确定性顺序执行
- **并且** `preAdapter` 转换应在命令适配器格式化之前运行
- **并且** `postAdapter` 转换应在适配器格式化之后运行

#### 场景：以声明方式应用工具特定重写

- **当** 工具需要指令重写（例如命令引用语法变更）时
- **则** 这些重写应作为具有显式适用性谓词的已注册转换来实现
- **并且** 生成入口点不应实现临时重写逻辑

### 需求：共享工件同步引擎

系统应提供一个由所有生成入口点使用的共享工件同步引擎。

#### 场景：init 和 update 使用相同引擎

- **当** `openspec init` 或 `openspec update` 写入技能/命令时
- **则** 两个流程应使用相同的编排引擎进行规划、渲染、验证和写入工件
- **并且** 行为差异应由配置驱动，而非单独的重复循环

#### 场景：遗留升级路径复用引擎

- **当** 遗留清理触发工件重新生成时
- **则** 重新生成路径应使用相同的共享引擎
- **并且** 生成的输出应遵循相同的转换和验证规则

### 需求：保真度护栏

系统应实施防止重构期间输出漂移的护栏。

#### 场景：投影一致性检查

- **当** CI 运行模板生成测试时
- **则** 应验证清单派生的投影保持一致（工作流、命令 ID、技能目录）
- **并且** 检测缺失的导出或缺失的工作流注册

#### 场景：输出一致性检查

- **当** 对具有代表性的工作流/工具组合运行一致性测试时
- **则** 生成的工件应在行为上等同于已批准的基线，除非有意更改
- **并且** 有意更改应在明确的规范/提案更新中捕获
