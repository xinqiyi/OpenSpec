# 探索 workflow 用户体验

## 背景

探索 workflow 是核心循环的一部分（`propose`、`explore`、`apply`、`archive`）。用户应该能够在探索 schema 下思考想法，然后平滑地过渡到正式的变更提议。

目前，explore 引用了正在被 `/opsx:propose` 替换的 `/opsx:new` 和 `/opsx:ff`。但除了更新引用之外，关于 explore 应该如何工作还有更深的用户体验问题。

这个探索也受到新兴 workspace 方向的影响：对于较大的跨团队或跨 repository 工作，OpenSpec 可能需要将**行动倡议**作为第一类 planning 对象，将 repository 本地变更作为执行产物。这意味着 explore 有时可能是在播种一个行动倡议，而不仅仅是一个单一的变更。

## 开放问题

### 探索产物

1. **探索结果应该能导出为 .md 吗？**
 - 目前探索是短暂的（仅仅是对话）
 - 用户是否会从保存探索笔记中受益？

2. **探索文件应该存放在哪里？**
 - `openspec/explorations/<name>.md`？
 - `openspec/changes/<change>/explorations/`？
 - 对于协调工作：`.openspec-workspace/initiatives/<initiative>/explorations/`？
 - 其他地方？

3. **格式应该是什么？**
 - 自由形式的 Markdown？
 - 结构化 template（问题、洞察、开放问题）？
 - 对话记录？

### 多个探索

4. **用户是否可以有一个变更相关的多个探索？**
 - 例如，分别探索认证方法和 UI 方法
 - 这些彼此之间如何关联？

5. **探索如何关联到变更或行动倡议？**
 - 变更存在前：独立探索
 - repository 本地变更存在后：探索链接到变更？
 - 对于协调工作：探索先链接到行动倡议，然后可选地被 repository 本地变更引用？

### 生命周期与转换

6. **在变更提议存在之前会发生什么？**
 - 探索是独立的
 - 准备好后，用户运行 `/opsx:propose`
 - 对于协调工作，探索上下文是否应首先播种一个行动倡议？
 - 探索上下文是否应自动播种提议？

7. **变更提议存在之后会发生什么？**
 - 探索可以引用现有产物
 - 探索应该能直接更新产物吗？
 - 还是仅仅告知用户要更新什么？

8. **explore 到 propose 的转换如何工作？**
 - 手动：用户复制洞察并单独运行 propose
 - 半自动：explore 提供"从此探索创建提议？"
 - 自动：explore 检测到想法成熟并主动开始 propose

### 上下文交接

9. **探索洞察如何流入提议？**
 - 用户手动整合洞察
 - 探索摘要成为 propose 提示的输入
 - 探索文件在提议中被链接/引用

10. **propose 应该能读取探索文件吗？**
 - "我看到你探索了认证方法。利用这些洞察..."

## 潜在方案

### 方案 A：短暂探索（现状增强版）
- 探索仍仅限对话
- 只需更新对 `/opsx:propose` 的引用
- 用户手动携带洞察前进
- **优点：** 简单，无新产物
- **缺点：** 洞察可能丢失，无审计跟踪

### 方案 B：可选导出
- 在结束时添加"保存探索"选项
- 保存到 `openspec/explorations/<name>.md`
- Propose 可以选择读取这些文件作为上下文
- **优点：** 选择加入的复杂性，保留洞察
- **缺点：** 需要管理的另一类产物

### 方案 C：探索作为提议种子
- 探索自动保存结构化笔记
- 当过渡到 propose 时，笔记成为提议输入
- **优点：** 无缝交接，保留上下文
- **缺点：** 更复杂，紧密耦合

### 方案 D：变更内的探索
- 变更前：独立探索
- 变更创建后：探索笔记存放在 `changes/<name>/explorations/` 中
- 产物可以引用探索笔记
- **优点：** 与变更关系清晰
- **缺点：** 变更前的探索放哪里？

### 方案 E：协调工作的行动倡议优先探索
- 本地工作可以保持独立或与变更链接
- 协调工作将探索笔记保存在协调 workspace 中的行动倡议下
- 当执行开始时，repository 本地变更可以引用共享探索
- **优点：** 匹配共享 planning 和 repository 本地执行之间的新兴分离
- **缺点：** 增加了探索产物可能存在的另一个上下文
