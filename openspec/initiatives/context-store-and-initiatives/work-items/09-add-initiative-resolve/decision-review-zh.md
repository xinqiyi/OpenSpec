# 事项 9 决定：拒绝倡议解析

## 最终决定

现在或以后都不实现独立的 `openspec initiative resolve <id>` 命令。

该命令不必要，因为它试图做已经属于其他概念的工作：

- `initiative show` 找到规范倡议。
- 工作区是仓库和文件夹的本地视图。
- 仓库本地变更将自己链接到倡议。
- 仓库本地状态报告工作进度。

## 决定 1：无命令

不需要独立的倡议命令。

如果用户只有上下文存储，`initiative show` 就足够了。如果用户有工作区，本地视图已经由该工作区代表。如果用户在仓库内部，仓库本地命令就足够了。

## 决定 2：本地解析属于工作区

工作区将本地仓库和文件夹映射到一台机器上的路径。未来能感知倡议的本地打开应属于工作区行为。

## 决定 3：代理行为

代理应：

- 对共享上下文使用 `openspec initiative show <id> --json`。
- 当用户在工作区中工作时，使用当前工作区视图。
- 当用户在仓库中工作时，使用仓库本地命令。
- 让用户决定哪些仓库在本地存在。

## 决定 4：被拒绝的范围

移除所有独立的解析行为：

- 没有 `initiative resolve`
- 没有全仓库扫描
- 没有全工作区扫描
- 没有 `--path` 搜索根
- 没有 Git 远程匹配
- 没有克隆
- 没有工作树或分支创建
- 没有倡议反向链接
- 没有本地可用性仪表板

将事项 9 转换为仅决策的检查点。

```text
`initiative show`；本地路径映射属于工作区；实施进度属于仓库本地变更。
```
