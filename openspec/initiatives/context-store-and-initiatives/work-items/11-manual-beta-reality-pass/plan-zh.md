# 手动 Beta 真实体验检查

## 状态

提议的下一个工作项。

## 目标

手动尝试当前的 beta 流程，在构建更多功能之前将摩擦点作为产品输入。

## 体验检查形式

从全新的本地设置开始，逐步完成：

- 上下文存储设置或注册
- 通过 agent 创建和编辑倡议
- workspace 打开
- workspace 链接或重新链接
- workspace 诊断
- 链接到倡议的 repository 本地变更创建
- 交还给 agent

## 输出

输出应为笔记，而非打磨：

- 哪些感觉容易
- 哪些感觉别扭
- 哪些标志泄露到了面向用户的文档中
- 哪些提示缺失
- 哪些需要显式告知 agent
- 哪些应成为后续的实施切片

## 非目标

- 不需要干净的公开教程状态。
- 不必解决体验检查中发现的每一个问题。
- 不要将 beta 流程变成进度仪表板。
