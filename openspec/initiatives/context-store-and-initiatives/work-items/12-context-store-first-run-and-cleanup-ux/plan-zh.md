# 上下文存储首次运行和清理 UX

## 状态

已实施。

此工作项涵盖了后续文档、架构或交接工作中未完全捕获的上下文存储设置和清理差距。

## 事实来源

手动 beta 注释：

- `../11-manual-beta-reality-pass/notes.md`，特别是关于无参数设置、清理、目标路径安全和共享存储 Git 指导的发现。

保留当前边界：

```text
上下文存储同步事实。
集合塑造事实。
倡议协调工作。
工作区打开本地视图。
变更实现仓库拥有的切片。
```

## 为什么存在

Beta 测试发现 `openspec context-store setup` 感觉像是一个首次运行入口点，但无参数设置目前不会引导用户完成他们需要做出的选择。测试还发现从错误的存储设置中恢复需要手动编辑注册表和删除文件。

这些是本地的生命周期问题，而不是共享协调模型问题。在要求新用户或团队成员信任上下文存储作为正常的本地工作流之前，应该解决这些问题。

## 目标

- 使无参数的 `context-store setup` 成为终端中友好的交互式设置路径。
- 保持非交互式和 JSON 行为确定且对代理安全。
- 在创建之前使目标存储路径明确。
- 提供受支持的本地清理命令，用于从此机器移除或注销上下文存储。
- 将 Git 设置限制为可选的本地初始化，无需暂存、提交、推送、创建远程仓库或选择团队工作流。

## 非目标

- 不添加远程仓库创建、克隆、拉取、推送、监视或同步自动化。
- 不让设置选择团队治理、分支或审查策略。
- 不经用户明确选择就删除共享文件。
- 不让上下文存储成为实施仓库。

## UX 方向

产品测试中锁定的决策：

- 在交互式终端中运行时，无参数的 `openspec context-store setup` 应启动引导式设置。代理、脚本、CI 和 `--json` 调用者应传递等效的显式输入，而不是依赖提示。
- 引导式设置应仅询问映射到现有设置标志的值：上下文存储 id、上下文存储路径以及是否初始化 Git。
- 面向用户的提示文案应保持直接：
  `上下文存储名称`、`此上下文存储应位于何处？`、`在此上下文存储中初始化 Git？`，然后在显示解析后的摘要后显示最终的`创建此上下文存储？`确认。
- 默认位置应为受管理的 OpenSpec 上下文存储目录，而不是当前工作目录。用户仍然可以选择任何明确的、安全的本地路径；OpenSpec 将该机器本地路径存储在本地注册表中，而不是共享的上下文存储元数据中。
- 设置应对风险路径具有保护性：创建缺失路径，接受空目录，将匹配的上下文存储元数据视为幂等，在元数据/id 冲突时停止，在有文件时停止，并在使用非空的未标记目录或另一个 Git 仓库内的路径时停止或显式警告。
- 清理应暴露两个明确的意图：`context-store unregister <id>` 忘记机器本地注册表条目并保留文件不变，而 `context-store remove <id>` 在显示确切路径并收到确认后，注销存储并删除本地文件夹。
- 成功路径的人类输出应保持小巧：显示上下文存储 id、其位置和下一个面向用户的步骤。不要显示 Git 状态、元数据路径、注册表路径或已创建的文件列表，除非有警告、失败、`--json` 或 `context-store doctor` 输出。
- JSON 输出应报告确切的结果状态，而不是工作流指导。包括 id、根路径、元数据路径、注册表状态、Git 事实、已创建/删除的文件以及存在的警告/错误，但不包括 `next_commands`。在现有 JSON 兼容性需要时，可以保留空的 `status: []`，但新行为不应依赖空状态数组来表达含义。
- Git 初始化是可选的本地便利功能。当请求时，OpenSpec 可以运行 `git init`，但不得暂存、提交、推送、创建远程仓库、创建分支或定义团队 Git 策略。

交互式设置应涵盖最少的选项：

```text
存储 id
目标路径，默认为受管理的 OpenSpec 上下文存储位置
是否初始化 Git
```

在写入文件之前，输出应显示解析后的目标路径。如果显式路径位于另一个 Git 仓库内或是一个现有的非空目录，命令应在交互模式下以清晰的措辞请求确认，或在非交互模式下失败并显示修复消息。

清理应区分本地注册和文件删除：

```bash
openspec context-store unregister team-context
openspec context-store remove team-context
```

命令名称是明确的，因为用户的意图不同：

- 仅忘记此本地注册表条目
- 也删除此本地上下文存储文件夹

如果 Git 初始化失败，设置应说明用户可以安装 Git 或在不使用 Git 的情况下重新运行设置。成功的 Git 初始化应保持在成功路径的人类输出之外。

## 代理 / JSON 契约

JSON 设置输出应报告：

- 存储 id
- 根路径
- 元数据路径
- 是否初始化了 Git
- 文件是已创建还是已存在
- 本地注册表路径或注册表条目标识

JSON 清理输出应报告：

- 存储 id
- 移除的本地注册表条目（如果有）
- 删除的根路径（如果请求）
- 留在磁盘上的文件（如果未请求删除）
- 关于缺失、歧义或已移除状态的警告

## 完成标准

- 新用户可以在终端中运行 `openspec context-store setup`，并被引导完成正常的本地设置路径，无需了解标志。
- 非交互式和 JSON 设置在缺少所需选项时仍可预测地失败。
- 错误的本地存储注册可以通过 CLI 移除，无需手动编辑注册表。
- 设置和清理输出使本地文件、注册表和 Git 状态变得明确。
