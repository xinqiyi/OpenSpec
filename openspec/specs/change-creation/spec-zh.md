# change-creation 规范

## 目的
提供用于编程创建和验证 OpenSpec 变更目录的实用工具。

## 需求
### 需求：变更创建
系统应提供以编程方式创建新变更目录的函数。

#### 场景：创建变更
- **当** 调用 `createChange(projectRoot, 'add-auth')`
- **则** 系统创建 `openspec/changes/add-auth/` 目录

#### 场景：拒绝重复变更
- **当** 调用 `createChange(projectRoot, 'add-auth')` 且 `openspec/changes/add-auth/` 已存在
- **则** 系统抛出错误，指示该变更已存在

#### 场景：必要时创建父目录
- **当** 调用 `createChange(projectRoot, 'add-auth')` 且 `openspec/changes/` 不存在
- **则** 系统创建完整路径，包括父目录

#### 场景：拒绝无效变更名称
- **当** 使用无效名称调用 `createChange(projectRoot, 'Add Auth')`
- **则** 系统抛出验证错误

### 需求：变更名称验证
系统应验证变更名称遵循 kebab-case 约定。

#### 场景：接受有效的 kebab-case 名称
- **当** 验证类似 `add-user-auth` 的变更名称时
- **则** 验证返回 `{ valid: true }`

#### 场景：接受数字后缀
- **当** 验证类似 `add-feature-2` 的变更名称时
- **则** 验证返回 `{ valid: true }`

#### 场景：接受单个单词
- **当** 验证类似 `refactor` 的变更名称时
- **则** 验证返回 `{ valid: true }`

#### 场景：拒绝大写字符
- **当** 验证类似 `Add-Auth` 的变更名称时
- **则** 验证返回 `{ valid: false, error: "..." }`

#### 场景：拒绝空格
- **当** 验证类似 `add auth` 的变更名称时
- **则** 验证返回 `{ valid: false, error: "..." }`

#### 场景：拒绝下划线
- **当** 验证类似 `add_auth` 的变更名称时
- **则** 验证返回 `{ valid: false, error: "..." }`

#### 场景：拒绝特殊字符
- **当** 验证类似 `add-auth!` 的变更名称时
- **则** 验证返回 `{ valid: false, error: "..." }`

#### 场景：拒绝前导连字符
- **当** 验证类似 `-add-auth` 的变更名称时
- **则** 验证返回 `{ valid: false, error: "..." }`

#### 场景：拒绝尾随连字符
- **当** 验证类似 `add-auth-` 的变更名称时
- **则** 验证返回 `{ valid: false, error: "..." }`

#### 场景：拒绝连续连字符
- **当** 验证类似 `add--auth` 的变更名称时
- **则** 验证返回 `{ valid: false, error: "..." }`

### 需求：工作区感知的变更创建
变更创建应支持仓库本地和工作区规划主目录。

#### 场景：从工作区根目录创建变更
- **给定** 命令从 OpenSpec 工作区根目录运行
- **当** 用户创建新变更时
- **则** OpenSpec 应在工作区规划路径下创建变更
- **并且** 不应在链接仓库的 `openspec/changes/` 目录下创建变更
- **并且** 当未提供显式模式时，应使用 `workspace-planning` 模式

#### 场景：从工作区内部创建变更
- **给定** 命令从 OpenSpec 工作区规划主目录的子目录中运行
- **当** 用户创建新变更时
- **则** OpenSpec 应将当前工作区解析为规划主目录
- **并且** 应在该工作区的规划路径下创建变更
- **并且** 当未提供显式模式时，应使用 `workspace-planning` 模式

#### 场景：从链接仓库内部创建变更
- **给定** 仓库或文件夹被注册为工作区链接
- **并且** 命令从该链接仓库或文件夹内部（而非工作区规划主目录）运行
- **当** 用户创建新变更且未显式选择工作区时
- **则** OpenSpec 应为该位置保留仓库本地变更创建行为
- **并且** 不应仅仅因为该位置被注册为工作区链接就创建工作区范围的变更

#### 场景：保留仓库本地变更创建
- **给定** 命令在 OpenSpec 工作区外部运行
- **当** 用户在仓库本地的 OpenSpec 项目中创建新变更时
- **则** OpenSpec 应继续在 `openspec/changes/` 下创建变更

#### 场景：拒绝无效的工作区影响领域
- **给定** 工作区变更创建请求包含影响领域名称
- **当** 一个或多个名称不是已注册的工作区链接时
- **则** OpenSpec 应拒绝这些无效的影响领域
- **并且** 应列出有效的工作区链接名称

#### 场景：无影响领域创建
- **给定** 用户仍在探索范围
- **当** 用户创建不带影响领域的工作区变更时
- **则** OpenSpec 应创建工作区变更
- **并且** 应允许稍后识别影响领域
