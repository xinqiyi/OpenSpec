# List 命令 spec

## 目的

`openspec list` 命令应为开发者提供项目中所有活跃变更的快速概览，显示其名称和任务完成状态。
## 需求
### 需求：命令执行
该命令应根据所选 schema 扫描并分析活跃变更或 spec。

#### 场景：扫描变更（默认）
- **WHEN** 执行 `openspec list` 时未带标志
- **THEN** 扫描 `openspec/changes/` 目录查找变更目录
- **AND** 从结果中排除 `archive/` 子目录
- **AND** 解析每个变更的 `tasks.md` 文件以统计任务完成情况

#### 场景：扫描 spec
- **WHEN** 执行 `openspec list --specs` 时
- **THEN** 扫描 `openspec/specs/` 目录查找能力
- **AND** 读取每个能力的 `spec.md`
- **AND** 解析需求以计算需求数量

### 需求：任务计数

该命令应使用标准 Markdown 复选框 schema 准确统计任务完成状态。

#### 场景：在 tasks.md 中统计任务

- **WHEN** 解析 `tasks.md` 文件时
- **THEN** 统计匹配以下 schema 的任务：
 - 已完成：包含 `- [x]` 的行
 - 未完成：包含 `- [ ]` 的行
- **AND** 计算总任务数为已完成和未完成之和

### 需求：输出格式
该命令应以清晰、可读的表格格式显示项目，并附带适合 schema 的进度或计数。

#### 场景：显示变更列表（默认）
- **WHEN** 显示变更列表时
- **THEN** 显示包含以下列的表格：
 - 变更名称（目录名）
 - 任务进度（例如 "3/5 任务" 或 "已完成"）

#### 场景：显示 spec 列表
- **WHEN** 显示 spec 列表时
- **THEN** 显示包含以下列的表格：
 - spec ID（目录名）
 - 需求数量（例如 "需求 12"）

### 需求：标志
该命令应接受标志来选择要列出的名词。

#### 场景：选择 spec
- **WHEN** 提供了 `--specs`
- **THEN** 列出 spec 而非变更

#### 场景：选择变更
- **WHEN** 提供了 `--changes`
- **THEN** 显式列出变更（与默认行为相同）

### 需求：空状态
当所选 schema 下没有项目时，该命令应提供清晰的反馈。

#### 场景：处理空状态（变更）
- **WHEN** 没有活跃变更存在（仅有 archive/ 或空的 changes/）
- **THEN** 显示："未找到活跃变更。"

#### 场景：处理空状态（spec）
- **WHEN** 没有 spec 目录存在或没有包含能力
- **THEN** 显示："未找到 spec。"

### 需求：错误处理

该命令应优雅地处理缺失的文件和目录，并附带适当的消息。

#### 场景：缺少 tasks.md 文件

- **WHEN** 变更目录没有 `tasks.md` 文件
- **THEN** 显示该变更的状态为"无任务"

#### 场景：缺少 changes 目录

- **WHEN** `openspec/changes/` 目录不存在
- **THEN** 显示错误："未找到 OpenSpec 变更目录。请先运行 'openspec init'。"
- **AND** 以退出码 1 退出

### 需求：排序

该命令应保持变更的一致排序，以获得可预测的输出。

#### 场景：变更排序

- **WHEN** 显示多个变更时
- **THEN** 按变更名称的字母顺序排序

## 为什么

开发者需要一种快速方式来：
- 查看哪些变更正在进行中
- 识别哪些变更可以 archive
- 了解整个项目的演进状态
- 无需打开多个文件即可获得全局视图

此命令以最小的努力提供这种可见性，遵循 OpenSpec 的简洁和清晰哲学。
