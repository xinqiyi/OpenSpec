# cli-view 规格说明

## 目的

`openspec view` 命令提供 OpenSpec 项目状态的综合仪表板视图，以统一、视觉吸引人的格式显示规格、变更和进度指标，帮助开发者快速了解项目状态。

## 需求

### 需求：仪表板显示

系统应提供一个 `view` 命令，显示规格和变更的仪表板概览。

#### 场景：基本仪表板显示

- **当** 用户运行 `openspec view` 时
- **则** 系统显示格式化的仪表板，包含摘要、活动变更、已完成变更和规格等部分

#### 场景：无 OpenSpec 目录

- **当** 用户在无 OpenSpec 的目录中运行 `openspec view` 时
- **则** 系统显示错误消息 "✗ No openspec directory found"

### 需求：摘要部分

仪表板应显示包含关键项目指标的摘要部分，包括草稿变更计数。

#### 场景：完整摘要显示

- **当** 仪表板渲染包含规格和变更时
- **则** 系统显示规格和需求的总数
- **并且** 显示草稿变更数量
- **并且** 显示进行中的活动变更数量
- **并且** 显示已完成的变更数量
- **并且** 显示总体任务进度百分比

#### 场景：空项目摘要

- **当** 没有规格或变更存在时
- **则** 摘要显示所有指标为零

### 需求：活动变更显示

仪表板应显示带有可视化进度指示器的活动变更。

#### 场景：活动变更按完成百分比排序

- **当** 多个活动变更显示进度信息时
- **则** 按完成百分比升序排列，使 0% 的项目排在最前面
- **并且** 将缺失的进度值视为 0% 进行排序
- **并且** 按变更标识符的字母升序打破平局，以保持输出确定性

### 需求：已完成变更显示

仪表板应在单独的部分中列出已完成的变更，仅显示所有任务都完成的变更。

> **修复 bug**：之前，`total === 0` 的变更被错误地显示为已完成。

#### 场景：已完成变更列表

- **当** 存在 `tasks.total > 0` 且 `tasks.completed === tasks.total` 的变更时
- **则** 系统在专用部分中以勾选标记指示符显示它们

#### 场景：混合完成状态

- **当** 部分变更已完成，其他为活动状态时
- **则** 系统将它们分隔到相应的部分

#### 场景：空变更不视为已完成

- **当** 变更没有 tasks.md 或定义了零个任务时
- **则** 系统不会将其显示在"已完成变更"部分
- **并且** 而是将其显示在"草稿变更"部分

### 需求：规格显示

仪表板应按需求数量排序显示规格。

#### 场景：带计数的规格列表

- **当** 项目中存在规格时
- **则** 系统按需求数量降序显示规格，并附计数标签

#### 场景：解析错误的规格

- **当** 规格文件无法解析时
- **则** 系统将其包含在内，需求计数为 0

### 需求：视觉格式

仪表板应使用一致的视觉格式，包含颜色和符号。

#### 场景：颜色编码

- **当** 显示仪表板元素时
- **则** 系统对规格项使用青色
- **并且** 对活动变更使用黄色
- **并且** 对已完成项使用绿色
- **并且** 对辅助文本使用暗灰色

#### 场景：进度条渲染

- **当** 显示进度条时
- **则** 系统使用实心块 (█) 表示已完成部分，使用浅色块 (░) 表示剩余部分

### 需求：错误处理

view 命令应优雅地处理错误。

#### 场景：文件系统错误

- **当** 文件系统操作失败时
- **则** 系统继续使用可用数据，并省略无法访问的项

#### 场景：无效数据结构

- **当** 规格或变更格式无效时
- **则** 系统跳过无效项并继续渲染

### 需求：草稿变更显示

仪表板应在单独的"草稿"部分中显示没有任务的变更。

#### 场景：草稿变更列表

- **当** 存在没有 tasks.md 或定义了零个任务的变更时
- **则** 系统在"草稿变更"部分中显示它们
- **并且** 使用不同的指示符（例如 `○`）表示草稿状态

#### 场景：草稿部分排序

- **当** 存在多个草稿变更时
- **则** 系统按名称字母顺序排序
