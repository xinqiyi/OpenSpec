# instruction-loader 规范

## 目的
instruction-loader 从模式目录加载指令模板，使用元数据和参数（如变更上下文和依赖状态）进行验证和丰富，并将其暴露给下游服务使用，包括模板检索、参数替换和丰富。

## 需求
### 需求：模板加载
系统应从模式目录加载模板。

#### 场景：从模式目录加载模板
- **当** 调用 `loadTemplate(schemaName, templatePath)`
- **那么** 系统从 `schemas/<schemaName>/templates/<templatePath>` 加载模板

#### 场景：模板文件未找到
- **当** 模板文件在模式的模板目录中不存在
- **那么** 系统抛出包含模板路径的错误

### 需求：变更上下文加载
系统应加载结合图谱和完成状态的变更上下文。

#### 场景：为现有变更加载上下文
- **当** 为现有变更调用 `loadChangeContext(projectRoot, changeName)`
- **那么** 系统返回包含图谱、完成集合、模式名称和变更信息的上下文

#### 场景：使用自定义模式加载上下文
- **当** 调用 `loadChangeContext(projectRoot, changeName, schemaName)`
- **那么** 系统使用指定的模式而非默认模式

#### 场景：为不存在的变更目录加载上下文
- **当** 为不存在的变更目录调用 `loadChangeContext`
- **那么** 系统返回包含空完成集合的上下文

### 需求：模板丰富
系统应使用变更特定上下文丰富模板。

#### 场景：包含工件元数据
- **当** 为工件生成指令时
- **那么** 输出包含变更名称、工件 ID、模式名称和输出路径

#### 场景：包含依赖状态
- **当** 工件有依赖项时
- **那么** 输出显示每个依赖项的完成状态（完成/缺失）

#### 场景：包含解锁的工件
- **当** 生成指令时
- **那么** 输出包含在此工件之后哪些工件变为可用

#### 场景：根工件指示器
- **当** 工件没有依赖项
- **那么** 依赖项部分指示这是一个根工件

### 需求：状态格式化
系统应将变更状态格式化为可读输出。

#### 场景：所有工件已完成
- **当** 所有工件完成时
- **那么** 状态显示所有工件为"完成"

#### 场景：混合完成状态
- **当** 部分工件完成时
- **那么** 状态显示已完成为"done"，就绪为"ready"，阻塞为"blocked"

#### 场景：阻塞工件详情
- **当** 工件被阻塞时
- **那么** 状态显示哪些依赖项缺失

#### 场景：包含输出路径
- **当** 格式化状态时
- **那么** 每个工件显示其输出路径模式
