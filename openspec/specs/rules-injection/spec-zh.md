# rules-injection 规范

## 目的
定义如何将项目配置中的按工件规则注入到生成的指令中，具有确定性的格式化和验证。

## 需求
### 需求：仅对匹配的工件注入规则

系统应仅在工件 ID 与 rules 对象中的键匹配时，才将配置中的规则注入到指令中。

#### 场景：工件存在规则
- **当** 为"proposal"加载指令且配置有 `rules: { proposal: ["Rule 1", "Rule 2"] }`
- **则** 指令输出包含包含两条规则的 rules 部分

#### 场景：工件无规则
- **当** 为"design"加载指令且配置有 `rules: { proposal: [...] }`
- **则** 指令输出不包含 `<rules>` 标签

#### 场景：Rules 对象未定义
- **当** 配置省略了 rules 字段或 rules 未定义
- **则** 指令输出不包含任何工件的 `<rules>` 标签

#### 场景：工件的 Rules 数组为空
- **当** 配置有 `rules: { proposal: [] }`
- **则** 指令输出不包含 `<rules>` 标签

### 需求：使用 XML 风格标签和项目符号列表格式化规则

系统应将规则包裹在 `<rules>` 标签中，每条规则作为项目符号列表项。

#### 场景：工件的单条规则
- **当** 配置有 `rules: { proposal: ["Include rollback plan"] }`
- **则** 指令输出包含 `<rules>\n- Include rollback plan\n</rules>\n\n`

#### 场景：工件的多条规则
- **当** 配置有 `rules: { proposal: ["Rule 1", "Rule 2", "Rule 3"] }`
- **则** 指令输出将每条规则作为单独的项目符号点

#### 场景：规则出现在 context 之后、template 之前
- **当** 同时包含 context 和 rules 生成指令时
- **则** 顺序为 `<context>` 然后 `<rules>` 然后 `<template>`

### 需求：完全按原样保留规则文本

系统应注入规则文本而不做修改、转义或解释。

#### 场景：规则包含 markdown
- **当** 规则包含 markdown 如 "Use **Given/When/Then** format"
- **则** markdown 在注入的内容中保留

#### 场景：规则包含特殊字符
- **当** 规则包含像 `<`、`>`、引号等字符
- **则** 字符完全按原样保留

#### 场景：规则是多行字符串
- **当** 规则文本包含换行符
- **则** 换行符在项目符号点内保留

### 需求：支持具有不同规则的多个工件

系统应允许同一配置中不同工件有不同的规则集。

#### 场景：多个工件有规则
- **当** 配置有 `rules: { proposal: ["P1"], specs: ["S1", "S2"], tasks: ["T1"] }`
- **则** proposal 指令仅显示 ["P1"]，specs 仅显示 ["S1", "S2"]，tasks 仅显示 ["T1"]

#### 场景：部分工件有规则，部分没有
- **当** 配置仅为 proposal 和 specs 设置了规则
- **则** design 和 tasks 指令没有 `<rules>` 部分

### 需求：规则是对 schema 指南的补充

系统应将配置规则添加到 schema 的内置工件指令中，而非替换它。

#### 场景：工件有 schema 指令和配置规则
- **当** 工件具有来自 schema 的内置指令且配置提供了规则
- **则** 最终指令同时包含 schema 指南和配置规则

#### 场景：规则提供额外约束
- **当** schema 说"创建 proposal"且配置规则说"包含回滚计划"
- **则** agent 同时看到 schema 模板和附加规则

### 需求：在指令加载时验证工件 ID

系统应在指令加载时针对 schema 验证规则中的工件 ID，并对未知 ID 发出警告。

#### 场景：所有工件 ID 有效
- **当** 指令加载且配置有 `rules: { proposal: [...], specs: [...] }` 对应具有这些工件的 schema
- **则** 不发出验证警告

#### 场景：规则中存在未知工件 ID
- **当** 指令加载且配置有 `rules: { unknownartifact: [...] }`
- **则** 发出警告："规则中存在未知工件 ID：'unknownartifact'。schema 'spec-driven' 的有效 ID：design、proposal、specs、tasks"

#### 场景：多个未知工件 ID
- **当** 指令加载且配置有多个未知工件 ID
- **则** 为每个未知工件 ID 发出单独的警告

#### 场景：每个会话仅显示一次验证警告
- **当** 同一 CLI 会话中多次加载指令
- **则** 每个唯一的验证警告仅显示一次（缓存）
